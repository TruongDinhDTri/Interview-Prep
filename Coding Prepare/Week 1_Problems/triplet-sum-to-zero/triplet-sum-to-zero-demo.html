Triplet Sum to Zero (3Sum)

From Unsorted Chaos to Sorted Harmony: The "Fix One, Solve Two" Strategy

🧠 The Mental Model

💡 Click Moment 1: The "Unsorted Trap"

The problem gives you an unsorted array. If you try to find triplets blindly, it's chaos ($O(N^3)$).
Insight: If we sort the array first ($O(N \log N)$), we gain the power of "Decision Making". Since the numbers are in order, we know exactly which way to move to make our sum bigger or smaller.

1. Fix One, Solve Two

It's hard to juggle 3 balls (A, B, C). So we stop one.

We Fix 'A' (using a loop). Now we just need to find two numbers B + C that equal -A.

This transforms a complex "3Sum" problem into a simple "Two Sum" problem!

2. Only Look Forward

When our iterator i is at index 2, should we look back at index 0 or 1?

NO. Any triplet involving index 0 would have already been found when i was at 0.

Always set left = i + 1. This prevents duplicate work.

💡 Click Moment 2: "Move Both Pointers"

You found a match! (e.g., -2, 0, 2). What now?

You must move BOTH pointers. Why? Because you have "used up" that specific combination. Moving just one would result in a sum that is definitely unbalanced (since the array has unique numbers mostly). To find a new combination, both need to shift.

🛑 Common Pitfalls (Don't fall for these!)

1. The "Logic Reversal" Bug

if (sum > 0) left++ ❌ WRONG!

If the sum is too big (Positive), moving left (to a bigger number) makes it WORSE.

Correct: If sum > 0 (Too Big), move right-- (to a smaller number).

2. The "Duplicate Ghost"

If your input is [-1, -1, 0, 1], and you don't skip the second -1, you will print the triplet [-1, 0, 1] twice!

Fix: while (arr[i] == arr[i-1]) continue;

        current_sum = arr[i] + arr[left] + arr[right]
