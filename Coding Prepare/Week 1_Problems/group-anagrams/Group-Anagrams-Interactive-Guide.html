📖 The Problem Statement
🎯 The Challenge: Given an array of strings, group the anagrams together.

📝 What are Anagrams?
Words that contain the same characters with the same frequencies, just rearranged!
• "eat", "tea", "ate" → All anagrams (same letters: e, a, t)
• "bat" → Not an anagram of the above (different letters)

💻 Example:
Input: ["eat", "tea", "tan", "ate", "nat", "bat"]
Output: [["eat", "tea", "ate"], ["tan", "nat"], ["bat"]]

🎨 Notice: Each group contains strings that are anagrams of each other!
🔍 Step 1: Pattern Detection
❌ Why NOT Two Pointers or Sliding Window?

Two Pointers → for pairs in sorted arrays, in-place modification, linked lists. None apply here!
Sliding Window → for contiguous subarrays, window validity, optimal lengths. None apply here!
✅ It's a GROUPING Problem → Hash Map!

• "Group anagrams together" — classic grouping scenario
• Need O(1) lookup to check if a group exists
• Multiple items per category (hashmap values = lists)
• Shared property (sorted string) → use as hashmap key → automatic grouping!
🗺️ Step 2: The Breakthrough

First instinct: compare character frequency maps of each pair. Good intuition, but O(n²) — too slow! Instead of comparing pairs, create a unique signature that ALL anagrams share.

💡 All anagrams produce the SAME sorted string!

• "eat" → sort → "aet"
• "tea" → sort → "aet" ← Identical!
• "ate" → sort → "aet" ← Identical!
• "bat" → sort → "abt" ← Different!

Use a hashmap: Key = sorted string, Value = list of original strings that sort to this key.

The Hashmap Structure 
hashmap = {
    "aet": ["eat", "tea", "ate"],  # All anagrams!
    "ant": ["tan", "nat"],         # All anagrams!
    "abt": ["bat"]                  # Only one string
}
📊 Step 3: Complexity

Derived from first principles via heapsort: heap height = log k, delete root k times → sorting one string = O(k log k). For n strings → O(n × k log k).

Space: storing all n strings (up to length k) in hashmap → O(n × k).

Metric Complexity Explanation
Time O(n × k log k) Sort k characters for each of n strings
Space O(n × k) Store all n strings in hashmap
⚖️ Step 4: Sorting vs Counting
Sorting (Chosen)

• O(k log k) per string
• Simple, readable, interview-friendly
Counting

• O(k) per string
• Faster, but more complex code

For typical k (≤ 100), the difference is negligible. "Premature optimization is the root of all evil" — Knuth.

🎓 The Signature Technique Pattern
When to Use: Find a property that's identical within a group, different across groups, and immutable (hashmap key).

Other Examples: Group by string length, by digit sum, by character frequency.

5 bugs, 5 lessons — click to expand details

#1 — In-Place Sorting: strings are immutable, can't use .sort() ▼
❌ Wrong
strs[i].sort()  # Strings have no .sort()!
✅ Right
''.join(sorted(strs[i]))  # sorted() → new list
💡 .sort() = list method (in-place, returns None) | sorted() = function (any iterable, returns new list)

Root cause: Assumed strings behave like lists. In Python, strings are immutable — they don't have a .sort() method.

Key difference: .sort() only works on lists, modifies in-place, returns None. sorted() works on any iterable (list, string, tuple), returns a NEW sorted list, doesn't modify original.

#2 — Join Syntax: separator calls join, not the list ▼
❌ Wrong
sorted(strs[i]).join('')  # Lists have no join!
✅ Right
''.join(sorted(strs[i]))  # separator.join(list)
💡 Python join is "backwards": separator.join(iterable), not iterable.join(separator)

Why it's backwards: The separator is a string, and join() is a string method. The separator "joins" the pieces together.

Examples: '-'.join(['a','e','t']) → "a-e-t" | ' '.join(['a','e','t']) → "a e t" | ''.join(['a','e','t']) → "aet"

#3 — Deferred Population: add the string NOW, not later ▼
❌ Wrong
key_hashmap["aet"] = []  # Empty... add later?
✅ Right
key_hashmap["aet"] = [strs[i]]  # Add right away!
💡 Don't defer — if you have data in hand, store it immediately

The trap: Thinking in two phases — "first create structure, then populate." But you already have the word "eat" when creating the key "aet".

The question that fixed it: "You have 'eat' right here in your hand — should you put it in the list now, or later?"

#4 — Extra List Nesting: [s] not [[s]] ▼
❌ Wrong
hashmap[key].append([strs[i]])  # [[s]] nesting!
hashmap[key] = [[strs[i]]]     # Double wrap!
✅ Right
hashmap[key].append(strs[i])   # Just the string
hashmap[key] = [strs[i]]      # List of one string
💡 [s] = list with one string | [[s]] = list with one list — know what you want!

The trap: Wrapping in extra [] when appending. .append([strs[i]]) adds a LIST to the list, creating [["eat"]] instead of ["eat"].

Debug question: "What do you actually want? A list of strings or a list of lists?" Answer: a list of strings.

#5 — Key Overwrite: check existence before assigning ▼
❌ Wrong
hashmap["aet"] = ["tea"]  # Overwrites "eat"!
✅ Right
if key in hashmap: hashmap[key].append(s)
else: hashmap[key] = [s]
💡 Always check-then-append, or use defaultdict(list) to auto-handle new keys

The bug: Assigning hashmap["aet"] = ["tea"] when "eat" was already stored under "aet" — overwriting silently.

Best fix: from collections import defaultdict → hashmap = defaultdict(list) → hashmap[key].append(s). Auto-creates empty list for new keys!

🎓 Key Takeaways
Python: sorted() vs .sort() | separator.join(iterable) | Only immutable types as dict keys
Patterns: Add data immediately | Check key existence before assignment | Know your nesting level
Mindset: Every bug is a lesson — debugging IS learning 🚀

class Solution:
    def groupAnagrams(self, strs: List[str]) -> List[List[str]]:
        """
        Group anagrams together from an array of strings.

        Args:
            strs: List of strings to group

        Returns:
            List of lists, where each inner list contains anagrams

        Time Complexity: O(n × k log k)
            - n = number of strings
            - k = maximum length of a string
            - Sorting each string takes O(k log k)

        Space Complexity: O(n × k)
            - Storing all n strings in the hashmap

        Example:
            >>> Solution().groupAnagrams(["eat","tea","tan","ate","nat","bat"])
            [["eat","tea","ate"], ["tan","nat"], ["bat"]]
        """
        # Edge case: empty input
        if not strs:
            return [[]]

        # Create hashmap to group anagrams
        key_hashmap = {}

        for i in range(len(strs)):
            # Create signature: sort characters alphabetically
            sorted_key = ''.join(sorted(strs[i]))

            # Add original string to the group
            if sorted_key in key_hashmap:
                key_hashmap[sorted_key].append(strs[i])
            else:
                key_hashmap[sorted_key] = [strs[i]]

        # Return all grouped anagrams
        return list(key_hashmap.values())
🚀 Cleaner Version with defaultdict
✨ Using defaultdict (Recommended) 
from collections import defaultdict

class Solution:
    def groupAnagrams(self, strs: List[str]) -> List[List[str]]:
        # defaultdict automatically creates empty list for new keys
        key_hashmap = defaultdict(list)

        for s in strs:
            # Create signature
            sorted_key = ''.join(sorted(s))

            # Add to group (no need to check if key exists!)
            key_hashmap[sorted_key].append(s)

        return list(key_hashmap.values())
Benefits of defaultdict:

• No need for if key in dict checks
• Automatically creates empty list for new keys
• Cleaner, more Pythonic code
• Fewer lines, less room for bugs
⚡ Alternative: Counting Approach (Advanced)
🎯 O(n × k) Solution More Complex 
from collections import defaultdict

class Solution:
    def groupAnagrams(self, strs: List[str]) -> List[List[str]]:
        key_hashmap = defaultdict(list)

        for s in strs:
            # Count character frequencies
            count = [0] * 26  # For 'a' to 'z'

            for char in s:
                count[ord(char) - ord('a')] += 1

            # Use tuple as key (lists aren't hashable)
            key = tuple(count)
            key_hashmap[key].append(s)

        return list(key_hashmap.values())
Trade-offs:

Counting Approach (O(n × k)):
✅ Faster time complexity
✅ No sorting overhead
❌ More complex code
❌ Harder to understand

Sorting Approach (O(n × k log k)):
✅ Simpler, cleaner code
✅ Easier to debug
✅ More interview-friendly
❌ Slightly slower (negligible for k ≤ 100)

If you have 100 strings, each with 50 characters, and you sort each string, what's the time complexity?

A) O(100 log 100) - sorting 100 items
B) O(100 × 50 log 50) - sorting 50 chars for each of 100 strings
C) O(100 × 50) - visiting each character once
D) O(50 log 50) - sorting just one string
✅ Correct! n = 100 strings, k = 50 characters. Sorting one string = O(k log k). For all strings = O(n × k log k) = O(100 × 50 log 50)

Question 4: Hashable Keys

Which of these can be used as a hashmap key in Python?

A) [1, 2, 3] - a list
B) {'a': 1, 'b': 2} - a dictionary
C) (1, 2, 3) - a tuple
D) {1, 2, 3} - a set
✅ Correct! Tuples are immutable and hashable. Lists, dicts, and sets are mutable and NOT hashable!

💡 Solution (Click to Reveal) 
def groupAnagramsStats(strs):
    from collections import defaultdict

    hashmap = defaultdict(list)

    for s in strs:
        key = ''.join(sorted(s))
        hashmap[key].append(s)

    groups = list(hashmap.values())

    # Number of groups
    num_groups = len(groups)

    # Largest group size
    largest = max(len(group) for group in groups)

    print(f"{num_groups} groups, largest group has {largest} strings")

    return groups
