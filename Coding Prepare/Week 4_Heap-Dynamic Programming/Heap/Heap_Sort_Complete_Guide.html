I. Representation of Binary Tree 🌳

When we represent a binary tree in an array, we care about two magical things:

  • Elements - The actual values in the tree 🎨
  • Relationships - How nodes connect to each other 🔗

🔗 Parent-Child Relationship Formulas

If a node lives at index i:

• Left child = 2 × i
• Right child = 2 × i + 1
• Parent = ⌊i / 2⌋ (floor division)
💡 Example:
If parent is at index 3.5 → floor(3.5) = 3 ✓
If parent is at index 2.5 → floor(2.5) = 2 ✓

II. Full | Complete Binary Tree 📐

1️⃣ Full Binary Tree

Definition: A full binary tree is where every node has either 0 or 2 children. No node has only one child! 🎯

  • Each internal (non-leaf) node has exactly two children
  • It's a tree full of nodes corresponding to its height
  • Adding any node increases the height
If a tree has height H, maximum nodes:

2h+1 - 1

(Every node has full children)

Example: Full Binary Tree (Height = 2)

Height = 2, Nodes = 22+1 - 1 = 7 ✓

2️⃣ Complete Binary Tree

Definition 1: A complete binary tree represented in an array wouldn't have any missing elements or gaps.
Definition 2: All levels are fully filled except possibly the last level, and in the last level, all nodes are as far left as possible. 🏗️🌳

The tree fills up level by level, left to right, with no gaps!

Complete Binary Tree Example:

Last level not full, but nodes 4, 5, 6 are packed left! ✓

📏 Height of Complete Binary Tree

The height of a complete binary tree will be MINIMUM:

height = ⌊log₂(n)⌋

We round DOWN (floor), not round up!

🔍 ANALYSE — Breaking It Down

To understand why height = ⌊log₂(n)⌋, we need to understand 3 things:

① Why 2h ?

How many nodes exist at each level?

② Geometric Series

How to sum all nodes across all levels?

③ Flip to Find h

Rearrange to solve for height from n.

① Why 2h ? — Each level doubles 🌳

Root = level 0. Every parent splits into 2 children → each level has double the nodes.

Pattern: Level 0 → 1 node  |  Level 1 → 2 nodes  |  Level 2 → 4 nodes  |  …  |  Level h → 2h nodes

② Geometric Series — Sum of All Nodes

A tree of height h has levels 0, 1, 2, …, h. Total nodes = sum across every level:

Total nodes = 20 + 21 + 22 + … + 2h

🪄 The Magic Trick — How to Prove This Sum

Let S = 1 + 2 + 4 + … + 2h   (the sum we want)

Step 1 — Write S:
S = 1 + 2 + 4 + … + 2h
Step 2 — Multiply both sides by 2:
2S = 2 + 4 + 8 + … + 2h+1
Step 3 — Subtract S from 2S:
2S − S = (2 + 4 + 8 + … + 2h+1) − (1 + 2 + 4 + … + 2h)

Almost everything cancels out! Only two terms survive:
Result:
S = 2h+1 − 1

🧮 Concrete example (h = 2):
S = 1 + 2 + 4 = 7   →   22+1 − 1 = 8 − 1 = 7 ✅

🤨 Why Subtract 1?

Think of it like binary counting:
2h+1 in binary = 1 followed by (h+1) zeros → e.g. 2³ = 1000
2h+1 − 1 = all 1s → e.g. 8 − 1 = 7 = 111

Subtracting 1 fills every bit below — just like filling every level of the tree! 🌳

Height h Nodes at level h Total nodes (all levels) Formula check
02⁰ = 112¹ − 1 = 1 ✓
12¹ = 21 + 2 = 32² − 1 = 3 ✓
22² = 41 + 2 + 4 = 72³ − 1 = 7 ✓
32³ = 81 + 2 + 4 + 8 = 152⁴ − 1 = 15 ✓

③ Flip the Formula — Solve for Height

We proved: n ≤ 2h+1 − 1 (a complete tree of height h holds at most that many nodes). Now flip it to find h from n:

Step 1 — Start with the max-nodes inequality:
n ≤ 2h+1 − 1
Step 2 — Add 1 to both sides:
n + 1 ≤ 2h+1
Step 3 — Take log₂ of both sides (log₂ preserves ≤):
log₂(n + 1) ≤ h + 1
Step 4 — Subtract 1:
h ≥ log₂(n + 1) − 1
Step 5 — Final answer (simplified):
h = ⌊log₂(n)⌋
(For a complete binary tree, log₂(n+1)−1 ≈ log₂(n), and we floor because height is a whole number.)
📝 Worked Example — n = 7 nodes

log₂(7) = 2.807…
⌊2.807⌋ = 2

✅ Height = 2 → The tree has levels 0, 1, 2 (exactly 3 levels).
A perfect tree of height 2 holds 2³ − 1 = 7 nodes — fits perfectly!

✅ Summary — The Beautiful Formulas:

Nodes at level h
2h
Max total nodes (height h)
2h+1 − 1
Height of complete tree
⌊log₂(n)⌋

III. Heap 🏔️

1️⃣ Heap is a Complete Binary Tree

A heap must always be a complete binary tree - filled level by level, left to right! 🌳

2️⃣ Max Heap

A complete binary tree where:

Every node ≥ all its descendants

👑 The largest element is the root!

3️⃣ Min Heap

A complete binary tree where:

Every node ≤ all its descendants

🔻 The smallest element is the root!

🎯 Key Properties:

  • Complete Binary Tree - Always filled level by level, left to right 🌳
  • Heap Property - Parent is always greater (Max) or smaller (Min) than children
  • Root is Special - Always the maximum or minimum element 👑
  • Efficient - Both Insert and Delete are O(log n)! ⚡

🌱 IV. Insert Operation

Inserting a new element into a heap is like planting a seed that grows upward, finding its rightful place among the branches! 🌳✨

🎯 Insert Rule: UPWARD Movement (LEAF → ROOT)

Step 1: Add the new element as the next available leaf (following complete binary tree rules: level by level, left to right)

Step 2: Compare with its parent

Step 3: If it violates heap property → SWAP

Step 4: Repeat until heap property is restored

Direction: 🍃 LEAF → 🌲 ROOT (moves UPWARD)

📚 Example: Insert 60 into Max Heap [50, 30, 20, 15, 10]

Initial Max Heap:
Step 1: Add 60 as next available leaf (left child of 20)

🌱 60 is planted as a leaf! But wait... 60 > 20 (parent) → violates Max Heap property!

Step 2: Compare 60 with parent 20 → SWAP!

⬆️ 60 climbs up! Now 60 > 50 (parent) → still violates!

Step 3: Compare 60 with parent 50 → SWAP!

👑 60 reaches the ROOT! Now it's the king of the heap! Max Heap property restored! ✨

⏱️ Time Complexity:

Best Case: O(1) - Element is already in correct position (e.g., inserting 6 into the heap above)

Worst Case: O(log n) - Element needs to travel from leaf to root (height of tree)

Average Case: O(log n)

🗑️ V. Delete Operation

In a heap, only the ROOT can be deleted - like picking the ripest apple from the top of the pyramid! 🍎👑

🎯 Delete Rule: DOWNWARD Movement (ROOT → LEAF)

⚠️ ONLY the ROOT element can be deleted! No other element! The root is always the maximum (Max Heap) or minimum (Min Heap).

Step 1: Delete the root element

Step 2: Replace root with the LAST LEAF (rightmost element at the deepest level)

Step 3: Compare new root with its children

Step 4: Swap with the LARGER child (Max Heap) if it violates heap property

Step 5: Repeat until heap property is restored

Direction: 👑 ROOT → 🍃 LEAF (moves DOWNWARD)

📚 Example: Delete from Max Heap [50, 30, 20, 15, 10, 8, 16]

Initial Max Heap:

Array: [50, 30, 20, 15, 10, 8, 16]

Step 1-2: Delete 50, replace with last leaf (16)

🔄 16 takes the root position. But 16 < 30 (left child) → violates Max Heap!

Step 3-4: Compare 16 with children (30, 20) → Swap with LARGER child (30)

⬇️ 16 sinks down! Now compare with children (15, 10)...

Step 5: Compare 16 with children (15, 10) → No swap needed! Heap property restored!

✨ Perfect! 16 > 15 and 16 > 10. Max Heap property restored!

💡 Key Observations:

  • After deletion: You always get the LARGEST (Max Heap) or SMALLEST (Min Heap) element
  • Next deletion: Gives you the NEXT LARGEST/SMALLEST element
  • Store deleted elements: Place them in the "freed space" at the end of the array
  • Result: Automatically creates a SORTED array! 🎉 This is Heap Sort!

⏱️ Time Complexity:

Worst Case: O(log n) - Element needs to travel from root to leaf (height of tree)

🎯 VI. Heap Sort - The Complete Process

Heap Sort is like a magical sorting spell with two enchanting steps! 🪄✨

📚 The Two Sacred Steps of Heap Sort:

STEP 1: 🏗️ Create a Heap - Build a Max Heap by inserting elements one by one

STEP 2: 🗑️ Delete All Elements - Remove the root repeatedly, storing deleted elements in freed spaces

Result: A beautifully sorted array! 🎉

⏱️ Time Complexity:
STEP 1: O(n log n) to build heap
STEP 2: O(n log n) to delete all
Total: O(n log n) 🚀

📊 Example: Sort [10, 15, 20, 30, 35, 40, 50]

🏗️ STEP 1: Build the Heap (Insert One by One)

Insert 10:

Array: [10]

Insert 15 → Compare with parent 10 → SWAP!

Array: [15, 10]

Insert 20 → Compare with parent 15 → SWAP!

Array: [20, 15, 10]

Continue inserting 30, 35, 40, 50... Final Max Heap:

✨ Max Heap Complete! Array: [50, 35, 40, 10, 30, 15, 20]

🗑️ STEP 2: Delete All Elements (One by One)

Delete 50 → Place in freed space → Heap size: 6

Sorted so far: [..., 50]

Delete 40 → Place in freed space → Heap size: 5

Sorted so far: [..., 40, 50]

Continue deleting... Final Result:

✨ Sorted Array ✨

🎯 The Magic of Heap Sort:

  • Each deletion gives you the NEXT LARGEST element (Max Heap)
  • Store deleted elements in the freed spaces at the end of the array
  • The array becomes sorted FROM THE BACK: [... 30, 35, 40, 50]
  • No extra space needed - sorting happens IN-PLACE! 🌟
  • Time: O(n log n) - Guaranteed! Works for any input!

🔄 VII. Heapify - The Efficient Way

There's a FASTER way to build a heap! Instead of inserting one by one, we can transform an array into a heap from bottom-up! 🚀✨

💡 What is Heapify?

Heapify is the process of converting an arbitrary array into a valid heap using DOWNWARD adjustments.

🎯 Key Insight: Leaf nodes are already valid heaps! So we only heapify NON-LEAF nodes!

📋 Bottom-Up Heapify Algorithm:

  1. Start from the LAST NON-LEAF node (index = n/2 - 1)
  2. Move BACKWARD through the array
  3. For each node: Apply DOWNWARD adjustment (same as delete operation)
  4. Continue until we reach the root (index 0)
⏱️ Time Complexity Comparison:
Insert One-by-One: O(n log n) ⏰
Bottom-Up Heapify: O(n) ⚡
Heapify is FASTER! 🚀

📊 Example: Heapify [10, 20, 15, 12, 40, 25, 18]

Initial Array (as Tree):

Array: [10, 20, 15, 12, 40, 25, 18] - NOT a Max Heap yet!

Last non-leaf node: Index = 7/2 - 1 = 2 (value: 15)

Heapify node at index 2 (value: 15)

Compare 15 with children (25, 18) → 25 > 15 → SWAP!

✅ Subtree rooted at 25 is now a Max Heap!

Heapify node at index 1 (value: 20)

Compare 20 with children (12, 40) → 40 > 20 → SWAP!

✅ Subtree rooted at 40 is now a Max Heap!

Heapify node at index 0 (value: 10) - THE ROOT!

Compare 10 with children (40, 25) → 40 > 10 → SWAP!

Now 20 is at root position, but it needs adjustment...

Continue heapifying downward... Final Max Heap!

🎉 Perfect Max Heap! Array: [40, 20, 25, 12, 10, 15, 18]

🚀 Why Heapify is Faster:

  • Leaf nodes (50% of tree): Already valid heaps - no work needed! ✨
  • Bottom nodes: Only move down 1 level
  • Middle nodes: Move down 2-3 levels
  • Root: Might move down log(n) levels
  • Mathematical analysis: Total work = O(n), NOT O(n log n)! 🎯

📊 Comparison:

Insert one-by-one: n insertions × O(log n) each = O(n log n)

Bottom-up heapify: O(n) - Much faster for large arrays! ⚡

👑 VIII. Priority Queue - The Royal Queue

A Priority Queue is like a royal court where the most important guests are served first! 🎩✨

🎯 What is a Priority Queue?

A Priority Queue is a special queue where elements are served based on their priority, not their arrival order.

  • 📥 Insert: Add elements with their priority
  • 📤 Delete: Always remove the HIGHEST (or LOWEST) priority element
  • 🎯 The element's VALUE is its PRIORITY

🔷 Min Priority Queue

Smaller number = Higher priority

Implemented with Min Heap

Example: Emergency room triage (severity level 1 = critical)

🔶 Max Priority Queue

Larger number = Higher priority

Implemented with Max Heap

Example: VIP service (level 10 = most VIP)

📊 Visual Comparison

Min Priority Queue (Min Heap)

Smaller = Higher Priority

Operations:
• Insert: O(log n) ⚡
• Delete Min: O(log n) ⚡
• Get Min: O(1) 🚀

Array: [1, 3, 5, 7, 9]

Max Priority Queue (Max Heap)

Larger = Higher Priority

Operations:
• Insert: O(log n) ⚡
• Delete Max: O(log n) ⚡
• Get Max: O(1) 🚀

Array: [9, 7, 5, 3, 1]

🔥 Why Use Heaps for Priority Queues?

Implementation Insert Delete Best?
Unsorted Array O(1) ⚡ O(n) 🐢 ❌
Sorted Array O(n) 🐢 O(1) or O(n) ⚡🐢 ❌
Heap (Min/Max) O(log n) ⚡ O(log n) ⚡ ✅✅✅

🌟 Heaps give us BOTH fast insert AND fast delete! Perfect balance! 🌟

🎭 Real-World Applications:

  • Operating System: CPU task scheduling (higher priority tasks run first)
  • Emergency Room: Patients triaged by severity (Min Heap - lower number = more urgent)
  • Dijkstra's Algorithm: Finding shortest paths (Min Heap for distances)
  • Event Simulation: Process events in time order (Min Heap by timestamp)
  • Huffman Coding: Data compression (Min Heap by frequency)
  • A* Pathfinding: Game AI and robotics (Min Heap by cost)
