Thought Process

How we derived the solution, step-by-step.

1. Pattern Recognition

We saw keywords: "contiguous", "maximum number", and "2 types".

💡 Insight This screams Sliding Window! Specifically, "Longest Substring with K Distinct Characters" (where K=2).

2. Fixed vs Variable?

Do we know the window size? No. We want the longest possible window.

Strategy: Variable Window. Expand right as much as possible, shrink left only when invalid.

3. Defining "Valid"

The core constraint is the baskets.

  • ✅ Valid: len(fruit_map) <= 2
  • ❌ Invalid: len(fruit_map) > 2

4. The "Shrink" Strategy

When the window becomes INVALID (3 types), we can't just skip the 3rd fruit. We must keep the contiguous block.

So, we move the Left Pointer forward, "throwing away" fruits from the tail until we are back to 2 types.

5. Data Structure Choice

Why a Hash Map {fruit: count} instead of a Set {fruit}?

Because when we remove a fruit from the left, we need to know if it's the last one of that type.

fruit_map[fruit] -= 1
if fruit_map[fruit] == 0:
  del fruit_map[fruit] # Only delete when count is 0

Interactive Quiz

Test your intuition.

Q1: Why do we shrink from the left?

To find the smallest fruit.
Because the subarray must be contiguous.
To reset the window completely.
Correct! Since the trees are contiguous, the only way to "fix" an invalid window while keeping the new fruit at the Right is to trim from the Left.

Q2: What is the Time Complexity?

O(n²) because of the nested while loop.
O(n) because each fruit is added and removed at most once.
O(log n) like Binary Search.
Correct! Even though there is a while loop inside the for loop, the Left pointer never moves backward. Both pointers traverse the array exactly once. Total operations = 2N.

Q3: When do we update max_length?

Inside the while loop (while invalid).
After the while loop (when valid).
Correct! We only care about the length of valid windows. We fix the window first, then measure it.

Code Walkthrough

Python 3 Solution.

class Solution: def totalFruit(self, fruits: List[int]) -> int: fruit_map = {} max_len = 0 left = 0 # Expand the window greedily for right in range(len(fruits)): current = fruits[right] fruit_map[current] = fruit_map.get(current, 0) + 1 # Shrink if INVALID (> 2 types in baskets) while len(fruit_map) > 2: left_fruit = fruits[left] fruit_map[left_fruit] -= 1 # Clean up the entry if count hits zero if fruit_map[left_fruit] == 0: del fruit_map[left_fruit] left += 1 # Move the window's tail # Update global max (current window is now valid) max_len = max(max_len, right - left + 1) return max_len
1 Initialization
We start with an empty map {}, left = 0, and max_len = 0.
2 Expansion Loop
The for right loop handles the expansion. We greedily add every fruit we see to our map.
3 The Shrink Condition
while len(fruit_map) > 2:
This is our "Validity Check". As long as we have 3+ types, we are invalid. We MUST shrink.
4 The Cleanup
if fruit_map[...] == 0: del ...
This is crucial. If we don't delete the key, len(fruit_map) will still be 3, and we'll be stuck in the loop forever!

Common Bugs

Don't fall into these traps!

🪲 Trap 1: Infinite Loop

Mistake: Forgetting left += 1 inside the while loop.

Result: You keep checking the same fruit at the same left index forever. The window never actually shrinks.

🪲 Trap 2: Zombie Keys

Mistake: Forgetting to del the key when count hits 0.

Result: Your map looks like {A: 0, B: 5, C: 2}. Python says length is 3. Code thinks it's invalid. You shrink until the window is empty!

✅ Trap 3: Wrong Max Update

Mistake: Updating max_len inside the while loop.

Result: You might count an invalid window (length 3 types) as a valid answer.

Fix: Always update max_len AFTER the while loop ensures validity.
