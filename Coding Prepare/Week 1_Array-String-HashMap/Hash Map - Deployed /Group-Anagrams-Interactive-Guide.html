📖 The Problem Statement
🎯 The Challenge: Given an array of strings, group the anagrams together.

📝 What are Anagrams?
Words that contain the same characters with the same frequencies, just rearranged!
• "eat", "tea", "ate" → All anagrams (same letters: e, a, t)
• "bat" → Not an anagram of the above (different letters)

💻 Example:
Input: ["eat", "tea", "tan", "ate", "nat", "bat"]
Output: [["eat", "tea", "ate"], ["tan", "nat"], ["bat"]]

🎨 Notice: Each group contains strings that are anagrams of each other!
🤔 Initial Thoughts

When first encountering this problem, the natural question is: "How do I identify which strings are anagrams?"

We need some way to compare strings and know instantly if they're anagrams without checking every possible pair (which would be too slow!).

🗺️ The Complete Journey

Step 1: The First Intuition

The journey began with a solid instinct - use a hashmap! But the question was: how exactly?

"How about using a hashmap and than i check if those 2 hashmap are the same?"

💭 The Thought Process:

This was thinking about comparing character frequency maps of each string. While the intuition was good, comparing every pair of strings would be O(n²) - too slow!

⚠️ The Challenge: How do we avoid comparing EVERY pair of strings? We need a smarter approach!

Step 2: The Breakthrough Moment!

Instead of comparing pairs, what if we could create a unique signature that ALL anagrams share?

💡 The Aha Moment: All anagrams produce the SAME sorted string!

🎯 Let's see it in action:
• "eat" → sort characters → "aet"
• "tea" → sort characters → "aet" ← Identical!
• "ate" → sort characters → "aet" ← Identical!
• "bat" → sort characters → "abt" ← Different!

✨ The Magic: Strings with the same sorted version are automatically anagrams!

🏗️ Building the Solution:

Now we can use a hashmap where:

  • Key: The sorted string (e.g., "aet")
  • Value: List of original strings that sort to this key
The Hashmap Structure 
hashmap = {
    "aet": ["eat", "tea", "ate"],  # All anagrams!
    "ant": ["tan", "nat"],         # All anagrams!
    "abt": ["bat"]                  # Only one string
}

Step 3: The Complexity Discussion

A fascinating deep dive into WHY sorting has the complexity it has!

"Wait a minute. The fastest sorting algorithm is nlogn right? let's say for heapsort. Each time we travel the heap is logn time. We delete the root and place it at the end of the array right? => n time we do that that's nlogn. => So let's say if the string is k characters => build a heap so it k height. => sort it it would k klogk. => n string would be n * klogk?"
🌟 Brilliant Reasoning!

You didn't just accept "sorting is O(n log n)" as a fact - you derived it from first principles by thinking through heapsort's mechanics:

For a heap with k elements:
• Height of heap = log k
• Deleting root (heapify down) = O(log k)
• Delete k times = k × log k = O(k log k)

For n strings:
• Each string: O(k log k)
• n strings total: O(n × k log k)

📚 The Learning:

Understanding why algorithms have certain complexities (not just memorizing) lets you:

  • Apply the concept correctly when the problem changes
  • Make informed decisions about trade-offs
  • Build genuine intuition about performance

Step 4: Sorting vs Counting - The Trade-off

An interesting alternative emerged: Instead of sorting, could we COUNT character frequencies?

Approach B: Counting
• Count character frequencies: O(k)

Pattern Recognition

How we identified the right approach

🔍 The Detective Work

Before jumping to hashmaps, let's understand WHY the patterns you already know (Two Pointers and Sliding Window) don't work here.

❌ Why NOT Two Pointers?
🚫 Two Pointers Pattern is for:

1. Finding Pairs/Triplets in Sorted Arrays
• Example: Two Sum in sorted array
• Use left and right pointers to find target sum
• This problem: NOT about finding pairs!

2. In-Place Array Modification
• Example: Remove duplicates from sorted array
• Use slow/fast pointers to filter in-place
• This problem: NOT modifying in-place!

3. Linked List Operations
• Example: Detect cycle, find middle
• Use fast/slow pointers
• This problem: NOT working with linked lists!

❌ Conclusion: No pairs, no in-place modification, no linked lists → NOT Two Pointers!
❌ Why NOT Sliding Window?
🚫 Sliding Window Pattern is for:

1. Contiguous Subarrays/Substrings
• Example: Longest substring with K distinct characters
• Expand window right, shrink when invalid
• This problem: NOT looking for subarrays!

2. Window Validity Conditions
• Example: Maximum sum of subarray with size K
• Maintain window that satisfies constraints
• This problem: NO window validity concept!

3. Longest/Shortest Subsequence
• Example: Minimum window substring
• Find optimal window length
• This problem: NOT about subsequence length!

❌ Conclusion: No contiguous subarray, no window validity, no length optimization → NOT Sliding Window!
✅ It's a GROUPING Problem!
🎯 Key Indicators This is Hash Map / Grouping:

1. The Problem Asks to "Group" Items
• "Group anagrams together"
• Need to categorize strings by shared property
• Classic grouping scenario!

2. Need O(1) Lookup
• Must quickly check if a group exists
• Hashmaps provide O(1) average lookup
• Perfect for this use case!

3. Multiple Items Per Category
• Each group can have many strings
• Hashmap values can be lists
• Natural fit for this structure!

4. Shared Property Identification
• All anagrams share same sorted string
• Use this as the hashmap key
• Automatic grouping!
🎯 The Pattern Recognition Framework
📚 When You See These Keywords → Think Hash Map:

• "Group" items by property
• "Categorize" elements
• "Organize" by shared characteristic
• "Count frequency" of items
• "Find duplicates" or unique items
• "Map" one thing to another

🎨 Other Examples:
• Group strings by length → Hash map: length → [strings]
• Group numbers by sum of digits → Hash map: sum → [numbers]
• Count character frequencies → Hash map: char → count

Complexity Analysis

Deep dive into time and space complexity

📊 Understanding the Complexity
⏱️ Time Complexity: O(n × k log k)

Let's break down where this comes from:

Variables:

• n = number of strings in the input array
• k = maximum length of a string
🧮 Derivation: The Heap Sort Method

You derived this complexity from first principles by thinking through heapsort! Here's how:

For ONE String of Length k:

Building a heap:

  • Height of heap with k elements = log k
  • Each heapify operation = O(log k)
  • Delete root and reheapify = O(log k)
  • Do this k times (for k elements) = k × log k

Result: Sorting one string = O(k log k)

For ALL n Strings:

If we sort n strings, and each sort costs k log k:

Total Time: n × (k log k) = O(n × k log k)

💡 Why This Is Brilliant:

You didn't just memorize "sorting is O(n log n)" - you understood WHY by thinking through the heap structure. This deeper understanding helps you apply it correctly when the "n" changes (here it's k characters, not n strings). Many people miss this distinction!
🎯 Alternative: Counting Approach

We discussed an alternative using character frequency counting:

Counting Approach 
def createKey(s):
    freq = [0] * 26  # For a-z

    for char in s:  # O(k) - loop through string
        freq[ord(char) - ord('a')] += 1

    # Convert to tuple (immutable) to use as key
    return tuple(freq)  # O(1) - only 26 elements

Time Complexity Breakdown:

  • Count characters: O(k) - visit each character once
  • Create tuple from 26-element array: O(1) - constant size
  • For n strings: O(n × k)
Approach Time Complexity Code Simplicity
Sorting O(n × k log k) ✅ Very Simple
Counting O(n × k) ⚠️ More Complex
📚 The Learning:

Understanding why algorithms have certain complexities (not just memorizing) lets you:

• Apply the concept correctly when the problem changes
• Make informed decisions about trade-offs
• Build genuine intuition about performance
💾 Space Complexity: O(n × k)

What we're storing:

  • Hashmap: Stores all n strings
  • Keys: Sorted versions (up to n distinct keys)
  • Values: Lists containing original strings

Worst case: All strings are unique (no anagrams), so we have n keys, each with one string of length k.

Total space: O(n × k)

Note: The space to store the output is not counted in space complexity analysis, since it's required by the problem.
📈 Complexity Summary
Metric Complexity Explanation
Time O(n × k log k) Sort k characters for each of n strings
Space O(n × k) Store all n strings in hashmap
🎯 Optimization Decision:

We chose sorting (k log k) over counting (k) because:

• For typical interview problems, k is small (k ≤ 100)
• The difference between k log k and k is negligible
• Sorting produces much cleaner, more readable code
• "Premature optimization is the root of all evil!"

🔴 Struggle #1: In-Place Sorting Confusion

Initial thought: "If I use sort() it will sort in-place and replace the actual value, right?"

❌ Attempted Code 
for i in range(len(strs)):
    strs[i].sort()  # Thinking this modifies the string in-place
    key_hashmap[strs[i]] = []

The problem: Strings in Python are immutable - they don't have a .sort() method at all!

The realization: Need to use sorted() which returns a NEW sorted list, then join it back into a string.

✅ Fix #1: Understanding sorted() vs sort()
Python Sorting Methods:

.sort() (method):
• Only works on lists
• Modifies list in-place
• Returns None

sorted() (function):
• Works on any iterable (list, string, tuple, etc.)
• Returns a NEW sorted list
• Doesn't modify the original
✅ Correct Approach 
s = "eat"
sorted_list = sorted(s)  # Returns ['a', 'e', 't']
# Still need to convert list back to string!

The confusion: "I don't know the syntax for join() sorry :)))"

❌ Wrong

The learning: Python's join() is backwards from intuition!

  • NOT: list.join(separator) ❌

The separator (a string) calls .join() on the iterable!

🎯 Final Solution Production Ready 
class Solution:
    def groupAnagrams(self, strs: List[str]) -> List[List[str]]:
        """
        Group anagrams together from an array of strings.

        Args:
            strs: List of strings to group

        Returns:
            List of lists, where each inner list contains anagrams

        Time Complexity: O(n × k log k)
            - n = number of strings
            - k = maximum length of a string
            - Sorting each string takes O(k log k)

        Space Complexity: O(n × k)
            - Storing all n strings in the hashmap

        Example:
            >>> Solution().groupAnagrams(["eat","tea","tan","ate","nat","bat"])
            [["eat","tea","ate"], ["tan","nat"], ["bat"]]
        """
        # Edge case: empty input
        if not strs:
            return [[]]

        # Create hashmap to group anagrams
        key_hashmap = {}

        for i in range(len(strs)):
            # Create signature: sort characters alphabetically
            sorted_key = ''.join(sorted(strs[i]))

            # Add original string to the group
            if sorted_key in key_hashmap:
                key_hashmap[sorted_key].append(strs[i])
            else:
                key_hashmap[sorted_key] = [strs[i]]

        # Return all grouped anagrams
        return list(key_hashmap.values())
🚀 Cleaner Version with defaultdict
✨ Using defaultdict (Recommended) 
from collections import defaultdict

class Solution:
    def groupAnagrams(self, strs: List[str]) -> List[List[str]]:
        # defaultdict automatically creates empty list for new keys
        key_hashmap = defaultdict(list)

        for s in strs:
            # Create signature
            sorted_key = ''.join(sorted(s))

            # Add to group (no need to check if key exists!)
            key_hashmap[sorted_key].append(s)

        return list(key_hashmap.values())
Benefits of defaultdict:

• No need for if key in dict checks
• Automatically creates empty list for new keys
• Cleaner, more Pythonic code
• Fewer lines, less room for bugs

from collections import defaultdict

class Solution:
    def groupAnagrams(self, strs: List[str]) -> List[List[str]]:
        key_hashmap = defaultdict(list)

        for s in strs:
            # Count character frequencies
            count = [0] * 26  # For 'a' to 'z'

            for char in s:
                count[ord(char) - ord('a')] += 1

            # Use tuple as key (lists aren't hashable)
            key = tuple(count)
            key_hashmap[key].append(s)

        return list(key_hashmap.values())
Trade-offs:

Counting Approach (O(n × k)):
✅ Faster time complexity
✅ No sorting overhead
❌ More complex code
❌ Harder to understand

Sorting Approach (O(n × k log k)):
✅ Simpler, cleaner code
✅ Easier to debug
✅ More interview-friendly
❌ Slightly slower (negligible for k ≤ 100)

Modify the solution to also print how many anagram groups exist and the size of the largest group.

Hint: After building the hashmap, what information can you extract from hashmap.values()?
💡 Solution (Click to Reveal) 
def groupAnagramsStats(strs):
    from collections import defaultdict

    hashmap = defaultdict(list)

    for s in strs:
        key = ''.join(sorted(s))
        hashmap[key].append(s)

    groups = list(hashmap.values())

    # Number of groups
    num_groups = len(groups)

    # Largest group size
    largest = max(len(group) for group in groups)

    print(f"{num_groups} groups, largest group has {largest} strings")

    return groups
