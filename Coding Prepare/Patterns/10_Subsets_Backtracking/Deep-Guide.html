🧬 The Parent Skeleton

Every problem on this page runs the exact same 5 steps. Nothing about this skeleton changes between them:

1. Choose one available option → 2. Recurse deeper → 3. if the GOAL is reached, snapshot the result → 4. Undo the choice → 5. try the next option.

It's tempting to think "backtracking = ask yes/no for each element," because Subsets looks that way. It doesn't hold up — trace Combination Sum instead (candidates=[2,3,6,7], target=7, coins reusable), where CHOICE is "pick 1 of 4 coins," not a binary yes/no:

path=[], remaining=7 1. CHOOSE coin 2 → path=[2], remaining=5 2. RECURSE with remaining=5 1. CHOOSE coin 2 again (reuse allowed) → path=[2,2], remaining=3 2. RECURSE with remaining=3 1. CHOOSE coin 3 → path=[2,2,3], remaining=0 2. GOAL reached (remaining==0) → SNAPSHOT [2,2,3] ✅ 3. UNDO coin 3 → path=[2,2], remaining=3 4. Try coin 6 → remaining=-3 → invalid, no snapshot, no recurse
The skeleton didn't move. Only CHOICE (which of several candidates) and GOAL (remaining==0, not "walked every element") changed. Backtracking is the technique; Subsets, Permutations, Combinations, Combo Sum are 4 fill-ins for CHOICE and GOAL — not 4 kinds of backtracking.
Đây là chỗ dễ hiểu lầm nhất: Backtracking KHÔNG PHẢI "yes/no mỗi phần tử" — đó chỉ là dáng vẻ của riêng Subsets. Coin trace ở trên cho thấy CHOICE có thể là "chọn 1 trong nhiều lựa chọn", còn khung xương thì không đổi. Backtracking là kỹ thuật cha; 4 bài toán bên dưới chỉ là 4 cách trả lời khác nhau cho CHỌN và LƯU.
🧩 The 4 Applications

Same skeleton — only CHOICE and GOAL change:

ProblemCHOICEGOAL (when to snapshot)
SubsetsForward only, never repeatEvery node — even []
PermutationsRescan all + used[]Only when full length
CombinationsForward only, same as SubsetsOnly when size == k
Combo SumForward, but reuse allowed (i)remaining==0, prune if <0

Why Permutations can't reuse Subsets' "forward only" rule: build [3,1,2] from [1,2,3] — pick index 2, then index 0 (which is before it), then index 1 (before 2, after 0). No "before/after" rule produces this order. Only marking which index is already used in this path (used[]) works — position doesn't matter, usage does.

Permutations không dùng được luật "chỉ tiến tới" của Subsets — thử dựng [3,1,2] sẽ thấy thứ tự index được chọn lộn xộn (2→0→1), không có luật trước/sau nào đúng. Chỉ có đánh dấu used[] mới work.
🪞 Two Equivalent Codings of Subsets

Not a decision to make per problem — two ways to draw the same tree, for Subsets specifically.

1. Include / Exclude — yes/no per element, fixed order, depth always = n:

def subsets(nums): result = [] def backtrack(i, path): if i == len(nums): result.append(path[:]); return path.append(nums[i]); backtrack(i + 1, path); path.pop() # take it backtrack(i + 1, path) # skip it backtrack(0, []) return result

2. Loop-based — snapshot at every call, then loop the rest to extend:

def subsets(nums): result = [] def backtrack(start, path): result.append(path[:]) # every path is already valid for i in range(start, len(nums)): path.append(nums[i]) backtrack(i + 1, path) path.pop() backtrack(0, []) return result

Trace both by hand for [1, 2] — identical 4 subsets: [], [1], [2], [1,2]. Loop-based is the one that generalizes to Combinations (len==k) and Combo Sum (reuse) — Include/Exclude's rigid "one yes/no per fixed position" doesn't stretch that far. That's why the other 3 applications all use Loop-based, not preference — it's the only shape that fits.

Include/Exclude và Loop-based KHÔNG PHẢI 2 pattern khác nhau để "chọn cái nào cho bài nào" — chúng ra CÙNG một cây cho Subsets. Loop-based mới generalize được sang Combinations/Combo Sum vì Include/Exclude không co giãn được cho "dùng lại" hay "thứ tự có nghĩa".
📸 Reference vs Snapshot

Say current = [1, 2] and at GOAL you do result.append(current) — no [:]. You didn't copy anything: result[0] now just points at the same list object as current. The moment you undo afterward (current.pop() → [1]), result[0] changes too — same object, not a separate one.

Fix: result.append(current[:]) — an actual copy, frozen at that instant, immune to whatever current does afterward.
Lưu con trỏ (không có [:]) chỉ lưu ĐỊA CHỈ của cái túi đang cầm — túi đó bị mutate liên tục, nên kết quả "đã lưu" cũng đổi theo. Phải chụp ảnh (current[:]) mới đóng băng đúng thời điểm.
