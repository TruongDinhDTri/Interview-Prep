Pattern 10 · Recognition

Subsets / Backtracking

⚡ Thẻ nhận diện nhanh — liếc signal là ra bài.

🎯 Spot it

The signals that scream Backtracking.

The words "generate ALL ___" — subsets, combinations, permutations, valid configs → walk the whole decision tree.

Nghe "liệt kê TẤT CẢ" (mọi subset / tổ hợp / hoán vị / cấu hình hợp lệ) → đi hết cây quyết định = Backtracking.
"generate ALL subsets/combinations/permutations"✓ backtracking
"all valid configurations" (N-Queens, Sudoku)✓ backtracking
"take or not take" each item✓ backtracking → subsets
"partition into two groups"✓ backtracking → subsets
"combinations that sum to target, reuse allowed"✓ backtracking → combo sum
"letter combinations of phone number"✓ backtracking → subsets-shaped
"count ways" / "find optimal (max/min)"✗ → DP instead
Hễ đề bảo đưa ra TẤT CẢ kết quả thì phải đi hết cây. Nhưng nếu chỉ hỏi "đếm số cách / tìm tối ưu" thì đó là DP, đừng dựng cây.

🧬 The parent skeleton

Backtracking is the cha — not a sibling.

Every problem below runs the exact same 5 steps. Choose an option → recurse deeper → if the GOAL is reached, snapshot the result → undo the choice → try the next option. It's tempting to think "backtracking = yes/no per element" because Subsets looks that way — it doesn't hold up. Trace Combination Sum instead, where CHOICE is "pick 1 of 4 coins," not a binary yes/no:

path=[], remaining=7   # candidates = [2,3,6,7], target = 7
1. CHOOSE coin 2 → path=[2], remaining=5
2. RECURSE with remaining=5
   1. CHOOSE coin 2 again (reuse allowed) → path=[2,2], remaining=3
   2. RECURSE with remaining=3
      1. CHOOSE coin 3 → path=[2,2,3], remaining=0
      2. GOAL reached (remaining==0) → SNAPSHOT [2,2,3] ✅
      3. UNDO coin 3 → path=[2,2], remaining=3
      4. Try coin 6 → remaining=-3 → invalid, no snapshot, no recurse
The skeleton didn't move. Only CHOICE (which of several candidates) and GOAL (remaining==0, not "walked every element") changed. Backtracking is the technique; Subsets, Permutations, Combinations, Combo Sum are 4 fill-ins for CHOICE and GOAL — not 4 kinds of backtracking.
Đây là chỗ dễ hiểu lầm nhất: Backtracking KHÔNG PHẢI "yes/no mỗi phần tử" — đó chỉ là dáng vẻ của riêng Subsets. Coin trace ở trên cho thấy CHOICE có thể là "chọn 1 trong nhiều lựa chọn", và khung xương (chọn→đi sâu→lưu nếu đủ điều kiện→undo→thử tiếp) không hề đổi. Backtracking là kỹ thuật cha; 4 bài toán bên dưới chỉ là 4 cách trả lời khác nhau cho CHỌN và LƯU.

🧩 4 applications

Same skeleton, different CHOICE + GOAL.

PROBLEM CHOICE GOAL (when to snapshot)
SubsetsForward only, never repeatEvery node — even []
PermutationsRescan all + used[]Only when full length
CombinationsForward only, same as SubsetsOnly when size == k
Combo SumForward, but reuse allowed (i)remaining==0, prune if <0

Why Permutations can't reuse Subsets' "forward only" rule: build [3,1,2] from [1,2,3] — pick index 2, then index 0 (before it), then index 1 (before 2, after 0). No "before/after" rule produces this order. Only marking which index is already used in this path (used[]) works — position doesn't matter, usage does.

Permutations không dùng được luật "chỉ tiến tới" của Subsets — thử dựng [3,1,2] sẽ thấy thứ tự index được chọn lộn xộn (2→0→1), không có luật trước/sau nào đúng. Chỉ có đánh dấu used[] mới work.

🪞 Not two patterns

Two equivalent codings of Subsets.

For Subsets specifically, two ways to write the code produce the exact same tree — not a decision to make per problem, two ways to draw the same picture.

1. Include / Exclude — yes/no per element, fixed order, depth always = n:

def subsets(nums):
    result = []
    def backtrack(i, path):
        if i == len(nums):
            result.append(path[:])
            return
        path.append(nums[i]); backtrack(i + 1, path); path.pop()   # take it
        backtrack(i + 1, path)                                     # skip it
    backtrack(0, [])
    return result

2. Loop-based — snapshot at every call, then loop the rest to extend:

def subsets(nums):
    result = []
    def backtrack(start, path):
        result.append(path[:])          # every path is already valid
        for i in range(start, len(nums)):
            path.append(nums[i])
            backtrack(i + 1, path)
            path.pop()
    backtrack(0, [])
    return result

Trace both by hand for [1, 2] — identical 4 subsets: [], [1], [2], [1,2]. Loop-based is the one that generalizes to Combinations (len==k) and Combo Sum (reuse) — Include/Exclude's rigid "one yes/no per fixed position" doesn't stretch that far. That's why the other 3 applications all use Loop-based, not preference — it's the only shape that fits.

Include/Exclude và Loop-based KHÔNG PHẢI 2 pattern khác nhau để "chọn cái nào cho bài nào" — chúng ra CÙNG một cây cho Subsets. Loop-based mới generalize được sang Combinations/Combo Sum vì Include/Exclude không co giãn được cho "dùng lại" hay "thứ tự có nghĩa".

🔀 Backtracking vs DP

Same tree, different question.

Include/Exclude and 0/1 Knapsack DP use the exact same "take or skip" tree. The only difference is what the problem asks you to return.

nums = [3, 4, 5], target = 7

                    TAKE 3              SKIP 3
                   /      \            /      \
              TAKE 4    SKIP 4    TAKE 4    SKIP 4
              /    \    /    \    /    \    /    \
            T5  S5  T5  S5   T5  S5  T5  S5

Same tree. Same decisions. 8 leaves.

"Give me ALL subsets that sum to 7" → need the full list → must visit every leaf:

[3,4]   sum=7 ✓ → collect
[3,5]   sum=8   → nope
[4,5]   sum=9   → nope
[3,4,5] sum=12  → nope
...

Answer: [[3,4]]          ← a LIST → Backtracking

"CAN any subset sum to 7?" → just yes/no → use a table, skip repeated work:

dp = [T, F, F, F, F, F, F, F]     ← make sum 0? yes. rest? no.
      0  1  2  3  4  5  6  7

After 3: [T, F, F, T, F, F, F, F]  ← can make 0 and 3
After 4: [T, F, F, T, T, F, F, T]  ← can make 7! done.

Answer: True              ← ONE value → DP
"give me ALL ___" → walk whole tree → Backtracking.
"can you / max / min / count" → just one answer → DP table.
Cùng một cây quyết định. Đề bảo liệt kê hết thì đi cả cây (Backtracking); đề chỉ cần một con số / có hay không thì lập bảng DP cho khỏi làm lại việc cũ.

🔁 Permutations

Order matters.

Start from 0 every time, track what's used.

def permutations(nums):
    result = []

    def backtrack(path, used):
        if len(path) == len(nums):
            result.append(path[:])
            return

        for i in range(len(nums)):
            if used[i]:
                continue
            used[i] = True
            path.append(nums[i])
            backtrack(path, used)
            path.pop()
            used[i] = False

    backtrack([], [False] * len(nums))
    return result
Hoán vị = thứ tự có nghĩa: mỗi lần bốc lại quét từ đầu, nhưng dùng mảng used để không lấy trùng một phần tử.

📸 The classic bug

Reference vs snapshot.

Say current = [1, 2] and at GOAL you do result.append(current) — no [:]. You didn't copy anything: result[0] now just points at the same list object as current. The moment you undo afterward (current.pop() → [1]), result[0] changes too — same object, not a separate one. By the end, every "saved" result looks like whatever current ended up as.

Fix: result.append(current[:]) — an actual copy, frozen at that instant, immune to whatever current does afterward.
Lưu con trỏ (không có [:]) chỉ lưu ĐỊA CHỈ của cái túi đang cầm — túi đó bị mutate liên tục (undo/pick), nên kết quả "đã lưu" cũng đổi theo. Phải chụp ảnh (current[:]) mới đóng băng đúng thời điểm.

👯 Handle duplicates

Skip the same value at the same level.

Sort first, then skip a repeated value at the same decision level:

nums.sort()
# inside the loop:
if i > start and nums[i] == nums[i - 1]:
    continue
Có phần tử trùng thì sort trước, rồi ở cùng một tầng bỏ qua giá trị đã dùng — nhờ vậy không sinh ra hai nhánh giống hệt.

⚠️ Traps

Where it breaks.

  1. Snapshot, don't reference — result.append(path[:]), not path (see above).
  2. Always undo — path.pop() after every recursive call, or state leaks across branches.
  3. CHOICE per problem: Subsets/Combinations → i + 1 · Permutations → 0 with used[] · Combo Sum → i to allow reuse.
Ba cái chết người: (1) quên snapshot nên kết quả bị đè; (2) quên pop() undo nên nhánh này dính nhánh kia; (3) nhầm CHOICE giữa 4 bài toán — subsets/combinations đi i+1, permutations quét từ 0 với used[], combo sum đi i để được dùng lại.
