Pattern 10 · Recognition

Subsets / Backtracking

⚡ Thẻ nhận diện nhanh — liếc signal là ra bài.

🎯 Spot it

The signals that scream Backtracking.

The words "generate ALL ___" — subsets, combinations, permutations, valid configs → walk the whole decision tree.

Nghe "liệt kê TẤT CẢ" (mọi subset / tổ hợp / hoán vị / cấu hình hợp lệ) → đi hết cây quyết định = Backtracking.
"generate ALL subsets/combinations/permutations"✓ backtracking
"all valid configurations" (N-Queens, Sudoku)✓ backtracking
"take or not take" each item✓ include/exclude
"partition into two groups"✓ include/exclude
"subset that sums to target"✓ include/exclude
"can you split array into equal halves?"✓ include/exclude
"letter combinations of phone number"✓ incl/excl per digit
"count ways" / "find optimal (max/min)"✗ → DP instead
Hễ đề bảo đưa ra TẤT CẢ kết quả thì phải đi hết cây. Nhưng nếu chỉ hỏi "đếm số cách / tìm tối ưu" thì đó là DP, đừng dựng cây.

🤔 Ask yourself

Which flavor of backtracking?

"For each element, yes or no?" → Include / Exclude.
"Which element do I pick next from the remaining?" → Loop-based backtracking.
Hai câu tự hỏi để chọn khung: hỏi "lấy hay không lấy?" thì đi Include/Exclude; hỏi "kế tiếp bốc thằng nào?" thì đi Loop-based.

🧠 Two mental models

Same tree, two ways to walk it.

1. Include / Exclude — at each element: take it or skip it. Two choices → 2ⁿ subsets.

nums = [1, 2, 3]

                    []
               /         \
          [1]               []           ← take 1? yes / no
         /    \           /    \
      [1,2]   [1]      [2]     []       ← take 2? yes / no
      / \     / \      / \     / \
[1,2,3][1,2][1,3][1] [2,3][2] [3] []   ← take 3? yes / no
def subsets(nums):
    result = []

    def backtrack(i, path):
        if i == len(nums):
            result.append(path[:])
            return

        path.append(nums[i])       # take it
        backtrack(i + 1, path)
        path.pop()                  # undo

        backtrack(i + 1, path)      # skip it

    backtrack(0, [])
    return result

Best for: whiteboard explanations, partition problems, subset sum.

2. Loop-based backtracking — save current path as valid, then loop remaining elements to extend it.

def subsets(nums):
    result = []

    def backtrack(start, path):
        result.append(path[:])          # every path is a valid subset

        for i in range(start, len(nums)):
            path.append(nums[i])
            backtrack(i + 1, path)
            path.pop()                  # undo

    backtrack(0, [])
    return result

Best for: combinations of size k, handling duplicates, permutations.

Cả hai đi cùng một cây. Include/Exclude hỏi lấy-hay-bỏ ở mỗi bước; Loop-based thì mỗi lần dừng đều lưu path rồi lặp phần còn lại để nối tiếp.

🔀 Backtracking vs DP

Same tree, different question.

Include/Exclude and 0/1 Knapsack DP use the exact same "take or skip" tree. The only difference is what the problem asks you to return.

nums = [3, 4, 5], target = 7

                    TAKE 3              SKIP 3
                   /      \            /      \
              TAKE 4    SKIP 4    TAKE 4    SKIP 4
              /    \    /    \    /    \    /    \
            T5  S5  T5  S5   T5  S5  T5  S5

Same tree. Same decisions. 8 leaves.

"Give me ALL subsets that sum to 7" → need the full list → must visit every leaf:

[3,4]   sum=7 ✓ → collect
[3,5]   sum=8   → nope
[4,5]   sum=9   → nope
[3,4,5] sum=12  → nope
...

Answer: [[3,4]]          ← a LIST → Backtracking

"CAN any subset sum to 7?" → just yes/no → use a table, skip repeated work:

dp = [T, F, F, F, F, F, F, F]     ← make sum 0? yes. rest? no.
      0  1  2  3  4  5  6  7

After 3: [T, F, F, T, F, F, F, F]  ← can make 0 and 3
After 4: [T, F, F, T, T, F, F, T]  ← can make 7! done.

Answer: True              ← ONE value → DP
"give me ALL ___" → walk whole tree → Backtracking.
"can you / max / min / count" → just one answer → DP table.
Cùng một cây quyết định. Đề bảo liệt kê hết thì đi cả cây (Backtracking); đề chỉ cần một con số / có hay không thì lập bảng DP cho khỏi làm lại việc cũ.

🔁 Permutations

Order matters.

Start from 0 every time, track what's used.

def permutations(nums):
    result = []

    def backtrack(path, used):
        if len(path) == len(nums):
            result.append(path[:])
            return

        for i in range(len(nums)):
            if used[i]:
                continue
            used[i] = True
            path.append(nums[i])
            backtrack(path, used)
            path.pop()
            used[i] = False

    backtrack([], [False] * len(nums))
    return result
Hoán vị = thứ tự có nghĩa: mỗi lần bốc lại quét từ đầu, nhưng dùng mảng used để không lấy trùng một phần tử.

👯 Handle duplicates

Skip the same value at the same level.

Sort first, then skip a repeated value at the same decision level:

nums.sort()
# inside the loop:
if i > start and nums[i] == nums[i - 1]:
    continue
Có phần tử trùng thì sort trước, rồi ở cùng một tầng bỏ qua giá trị đã dùng — nhờ vậy không sinh ra hai nhánh giống hệt.

⚠️ Traps

Where it breaks.

  1. Copy the path — result.append(path[:]), not path (it's a reference, it'll mutate).
  2. Always undo — path.pop() after every recursive call, or state leaks across branches.
  3. Subsets: i + 1 to avoid reusing — Permutations: start at 0 with used[].
Ba cái chết người: (1) quên copy path nên kết quả bị đè; (2) quên pop() undo nên nhánh này dính nhánh kia; (3) subsets đi i+1, còn permutations quét từ 0 với used[].
