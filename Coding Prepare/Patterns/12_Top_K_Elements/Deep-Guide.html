The core idea

A 3-seat club with a bouncer.

You want the 3 largest numbers from a long stream — say 3, 1, 5, 12, 2, 11. The lazy way is to sort all of them and take the last 3 (O(n log n)). But you don't care about the order of the losers — you only ever need to hold onto the best 3 so far.

So run a tiny club with exactly 3 seats. The bouncer stands at the door, and the bouncer is the weakest member currently inside:

club: 5 · 11 · 12
bouncer = 5 (weakest inside)

A new number walks up. Is it bigger than the bouncer (5)? If yes — it's stronger than the weakest member, so the bouncer gets kicked out and the newcomer takes the seat. If no — it can't beat even the weakest, so it's turned away. The club always holds the best 3.

Keep a size-K heap; its root is the bouncer — the weakest of the current top K. Push each element; if the club overflows past K, pop the root (evict the bouncer). The survivors are your top K. O(n log K) — way cheaper than sorting when K is small.

Shape one of two

① K largest — guard with a min-heap.

Largest → min-heap

K largest

Counter-intuitive but exact: to keep the K largest, the gatekeeper must be the smallest of them — so use a min-heap. Its root is the easiest to beat and the first to be evicted.

The idea

Push everything; whenever the heap exceeds K, pop the min (root). That root is the smallest of the current top-K — if a bigger number arrives, kicking the root out keeps the club strong. After the stream, the heap holds the K largest; its root is the Kth largest.

The movement — watch the gatekeeper evict

K = 3 largest from the stream 3 1 5 12 2 11.

min-heap · size ≤ 3 · root = weakest

The code

import heapq
def k_largest(nums, k):
    heap = []                       # min-heap
    for num in nums:
        heapq.heappush(heap, num)
        if len(heap) > k:
            heapq.heappop(heap)     # evict the weakest (min root)
    return heap                     # the K largest; heap[0] = Kth largest

Lives in: K largest · Kth largest element · K most frequent (count first, then top-K on counts).

Shape two of two

② K smallest — guard with a max-heap.

Smallest → max-heap

K smallest

Mirror image: to keep the K smallest, the gatekeeper is the largest of them — a max-heap. A new element gets in only if it's smaller than that gate.

The idea

Same engine, opposite heap. Python only has a min-heap, so simulate a max-heap by negating values on the way in (and out). The root (most-negative = largest original) is the gatekeeper to evict.

The movement — the largest gets kicked

K = 3 smallest from 8 3 9 1 7 2.

max-heap · size ≤ 3 · root = largest
The flip everyone trips on

K largest → MIN-heap. K smallest → MAX-heap. The gatekeeper is always the opposite extreme of what you want, because it must be the easiest member to throw out when a better candidate shows up.

K largest → min-heap (gate = smallest). K smallest → max-heap (gate = largest). Same core: a size-K heap, evict the gatekeeper when beaten. (Median of a stream → two heaps, see Pattern 15.)

You own it when…

The test.

  • Core idea in one line: keep a size-K heap; the root is the weakest member.
  • You pick the heap by the flip: largest → min-heap, smallest → max-heap.
  • You know Python needs negation to fake a max-heap.
  • “Kth largest” → heap root after the stream; “median of stream” → Two Heaps, not this.
