Pattern 09

MergeIntervals.

One core idea — sort by start, and every interval only touches its neighbour. Press step and watch the bars merge.

The core idea

Sort first — then chaos becomes a line.

Thrown together, any interval could overlap any other — checking all pairs is O(n²). But there's a hidden order you can impose for free.

Once you sort by start time, the intervals line up left to right. Now a new interval can only overlap the one just before it — never anything earlier. So one left-to-right pass, comparing each to the last, settles everything.

Sort by start → each interval only meets its predecessor. Overlap test: curr.start <= prev.end. One sweep merges or appends. O(n log n) (the sort dominates; the sweep is O(n)).

Shape one of two

① Merge — fuse what overlaps.

Combine overlaps

Sort & merge

Walk the sorted intervals. If the current one starts before the last result ends, they overlap — stretch the result's end. Otherwise it's a fresh interval — append it.

The idea

Keep a result list; its last entry is the “live” interval. For each next interval: overlap (curr[0] <= prev[1]) → extend with prev[1] = max(prev[1], curr[1]) (the max matters — curr might sit fully inside prev). No overlap → start a new live interval.

The movement — watch overlaps fuse

Merge [1,3] [2,6] [8,10] [9,12] (already sorted by start).

The code

def merge(intervals):
    intervals.sort(key=lambda x: x[0])     # sort by start — always first
    res = [intervals[0]]
    for curr in intervals[1:]:
        prev = res[-1]
        if curr[0] <= prev[1]:           # overlap
            prev[1] = max(prev[1], curr[1])  # extend (max!)
        else:
            res.append(curr)              # fresh interval
    return res

Lives in: merge overlapping · insert interval · “any meeting conflict?” (Meeting Rooms I).

Shape two of two

② Line sweep — count what's concurrent.

Events · concurrency

Line sweep (±1 events)

When you need how many overlap at once (not which), forget the intervals — split each into two events: +1 at start, −1 at end. Sort all events by time, sweep, track the running total.

The idea

Meeting Rooms II (min rooms): each +1 is someone arriving, each −1 is leaving. Sweeping left to right, the running counter is the number of concurrent meetings; its peak is the rooms you need.

The movement — watch the counter peak

Rooms for [1,5] [2,6] [4,7] — sweep the start/end events.

The code

def min_rooms(intervals):
    events = []
    for s, e in intervals:
        events.append((s, 1))   # +1 arrive
        events.append((e, -1))  # -1 leave
    events.sort()
    curr = peak = 0
    for _, delta in events:
        curr += delta
        peak = max(peak, curr)        # the answer = the peak
    return peak

Lives in: Meeting Rooms II · max concurrent events · CPU/airport load.

Merge answers “what are the combined intervals?” — sweep & extend. Line sweep answers “how many overlap at the busiest moment?” — ±1 events & a running peak. Same root: sort by time, then one pass.

You own it when…

The test.

  • Core idea in one line: sort by start, each interval only meets its predecessor.
  • You always sort first, and merge with max(prev.end, curr.end) (curr may be contained).
  • “Which combined intervals?” → merge. “How many concurrent / min rooms?” → line sweep.
  • You can split intervals into ±1 events and read the peak.
