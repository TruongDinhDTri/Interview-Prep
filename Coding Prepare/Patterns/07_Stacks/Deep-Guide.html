Pattern 07 · Stacks & Monotonic

Last in,first out.

A stack is a memory of what's still waiting. The top guards the order — and that single rule splits into two shapes that solve half your interview.

⚡ Recognition — thẻ nhận diện nhanh →

The one idea

It holds the unresolved.

A stack keeps the items that haven't been answered yet — newest on top, because the newest is the first that can be resolved.

An open ( waits for its ). A number waits for its operator. A bar waits for the next taller bar. Every stack problem is the same heartbeat: push what's pending, pop the moment it's resolved. Each element is pushed once and popped once → O(N).

Push when an item must wait. Pop when the thing it was waiting for arrives. The top is always the most-recent unresolved item — that's why LIFO is the right tool.

Two shapes, one breath

Which stack are you holding?

Shape A · Regular Stack

Pending matches

"Things wait in order, and resolve in reverse."

Signals: balanced / valid parentheses, postfix / RPN / evaluate expression, operator fires on the previous operands. You push items as they arrive; when a closer/operator shows up, it consumes the top.

RPN — operand order is the trap

for token in tokens:
    if token not in ops:        # isdigit() breaks on "-11" — use this
        stack.append(int(token))
    else:
        right = stack.pop()       # top is the RIGHT operand
        left  = stack.pop()
        stack.append(ops[token](left, right))   # LEFT op RIGHT — order matters
return stack.pop()
Trap Division: int(a/b) truncates toward zero; a//b floors — different for negatives. And use a plain list: append + pop are O(1).
Shape B · Monotonic Stack

Waiting for an answer

"Each element waits until a bigger (or smaller) one resolves it."

Signals: next greater / smaller, previous greater / smaller, days until warmer, span. The stack holds indices of unresolved elements; when a new element beats the top, it answers everyone it's bigger than.

Next Greater — the core

def nextGreater(nums):
    res = [-1] * len(nums)
    stack = []                       # INDICES, not values
    for i, num in enumerate(nums):
        while stack and num > nums[stack[-1]]:
            res[stack.pop()] = num    # num answers the one waiting
        stack.append(i)
    return res
The flip Want greater → keep a decreasing stack (pop when curr > top). Want smaller → keep an increasing stack (pop when curr < top).

Watch it resolve

The monotonic stack, breathing.

Finding the next greater element for each. Step through — watch indices pile onto the stack while they wait, then get answered and popped the instant a bigger number arrives.

Each index is pushed exactly once and popped at most once. The inner while looks scary, but across the whole run it can't pop more than N times total — so the two loops together are still linear.

You own it when…

The test.

  • Core idea in one line: a stack holds what's still unresolved; top = newest pending.
  • You pick the shape: matching/RPN → regular stack; next-greater/smaller → monotonic.
  • Monotonic: you store indices, you check stack and … first, and you know greater → decreasing, smaller → increasing.
  • RPN: LEFT op RIGHT (top is the right operand), and int(a/b) not a//b.
  • You can say why it's O(N): each element pushed once, popped once.
