The core idea

You already know what sorted looks like.

Here is the exact problem (LeetCode #75, “Sort Colors”). You hold an array where every element is 0, 1, or 2 — nothing else:

messy input

Normal sorting compares pairs to discover the order — O(n log n). But here the order is no mystery: there are only three values, so the answer is always “all 0s, then all 1s, then all 2s.” You never need to compare anything — you only need to shove each value into its band.

Tiny known value-set ⇒ you don't sort, you sweep into buckets. O(n), no comparisons. Two tools do it — pick by the constraint you're given:

Counting sort

Pass 1: tally how many of each value. Pass 2: overwrite the array in the order you choose — all 0s, then 1s, then 2s. The sorted order comes from your write-order, not from any comparison.

The idea

One shared write-cursor marches across the array, painting count[0] zeros, then count[1] ones, then count[2] twos. The cursor never resets — a fresh loop per value would restart at 0 and overwrite your work.

The movement — count, then repaint

Sort colours 2 0 2 1 0 by counting.

The code

from collections import Counter
def sort_colors(nums):
    c = Counter(nums)
    i = 0
    for v in (0, 1, 2):        # WE choose the order
        for _ in range(c[v]):
            nums[i] = v; i += 1   # ONE cursor, never reset

Lives in: sort a tiny value-set · character bucketing · the simple first answer before the O(1) follow-up.

Dutch National Flag

The follow-up: one pass, no extra space. Picture the array splitting into three growing zones — push 0s to the far left, 2s to the far right, and the 1s end up in the middle by themselves.

The idea — one scanner, three outcomes

Only one pointer does the looking: mid. It walks through the unknown middle. left marks where the 0-zone ends, right marks where the 2-zone begins. For each value mid lands on:

  • sees a 0 → it belongs far left → swap it down to the left zone, grow that zone (left++), and mid++.
  • sees a 1 → it's already in the right place (the middle) → just mid++.
  • sees a 2 → it belongs far right → swap it up to the right zone, grow that zone (right−−), but mid does NOT move.

The movement — three regions grow

Sort 2 0 2 1 0 1 in one pass.

left: 0smid: unknownright: 2s

The code

def sort_colors(nums):
    left, mid, right = 0, 0, len(nums) - 1
    while mid <= right:                  # <= : process the LAST slot too
        if   nums[mid] == 1: mid += 1
        elif nums[mid] == 0:
            nums[left], nums[mid] = nums[mid], nums[left]
            left += 1; mid += 1          # newcomer already scanned → mid advances
        else:                            # == 2
            nums[right], nums[mid] = nums[mid], nums[right]
            right -= 1                     # newcomer UNSEEN → mid STAYS
Why mid stays after a 2-swap

A 0-swap pulls a value from behind mid (already scanned, safe) → mid moves on. A 2-swap pulls a value from the unexplored right → it's never been looked at, so mid must re-examine the same slot. Advance mid there and you'd skip an unchecked value. (And the loop is mid <= right, not < — else the final slot is left unsorted.)

Counting sort = tally then repaint (2 passes, O(k) space — the easy answer). Dutch Flag = three pointers, one pass, O(1) space (the follow-up). Same root: a tiny value-set → partition, don't compare.

You own it when…

The test.

  • Core idea in one line: few possible values → bucket, don't compare.
  • Counting sort: one shared cursor, write-order is yours, don't clear the array first.
  • Dutch Flag: mid stays after a 2-swap, advances after a 0-swap; loop is mid <= right.
  • You compare nums[mid] (the value), never mid (the index).
