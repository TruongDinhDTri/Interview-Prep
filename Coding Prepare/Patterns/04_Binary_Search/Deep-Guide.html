Pattern 04

BinarySearch.

One core idea — throw away half every step. Press step and watch the search space collapse.

⚡ Recognition — thẻ nhận diện nhanh →

The core idea

It's not “sorted” — it's monotonic.

Everyone learns binary search as “a sorted array.” The real requirement is deeper: a monotonic predicate — a yes/no test that is false … false, then true … true, and never flips back. Sortedness is just one way to get that line.

FFFTTT

Binary search hunts the flip point. Check the middle: if it's on the false side, the flip is to the right — delete the left half. If true, the flip is here or left — delete the right half. One test kills half the candidates.

Halve the search space with one comparison. Each step throws away half: n → n/2 → n/4 → … → 1 = O(log n). The only thing you ever need is a monotonic question — then the middle's answer tells you which half cannot contain what you seek.

Shape one of two

① Find exact — is it here?

The hit-or-miss

Find exact

A sorted array; find the index of a target. Compare the middle to the target and discard the half that can't hold it — including the mid itself.

The idea

Sorted ⇒ the middle value tells you direction. nums[mid] < target ⇒ everything from left..mid is too small ⇒ jump left = mid+1. Bigger ⇒ right = mid−1. Equal ⇒ done. The loop is while left <= right because a single leftover cell still needs checking.

The movement — watch half vanish each step

Find 9 in [1, 3, 5, 7, 9, 11, 13].

The code

def binary_search(nums, target):
    left, right = 0, len(nums) - 1
    while left <= right:                  # <= : the last lone cell still counts
        mid = left + (right - left) // 2   # overflow-safe midpoint
        if   nums[mid] == target: return mid
        elif nums[mid] <  target: left  = mid + 1  # kill left half + mid
        else:                    right = mid - 1  # kill right half + mid
    return -1

Lives in: search a sorted array · search a rotated sorted array (find which half is sorted first).

Shape two of two

② Find boundary — where does it flip?

The flip-finder

Find boundary (first true)

Forget “find a value.” Here you find a border — the one place where the world turns from NO to YES and never turns back. This is the real power of binary search.

Picture it — a hallway of lamps 🚪

A row of rooms. The first few are dark 🌑; then from one door onward every room is lit 💡 — and never goes dark again. Exactly one door is the dark→lit border. You want the first lit room. You can't see the hallway — you may only walk into one room and ask “is this room lit?”

⚠️ The one line everyone gets wrong: why right = mid, not mid − 1?

In Find Exact, a non-matching mid is useless → you toss it (mid − 1). Here it's the opposite: a lit mid could BE the first lit room. Write right = mid − 1 and you'd throw away the very answer you're standing in. So a lit room is never discarded — you only shrink the search up to it: right = mid. Lit = keep. Dark = drop. That single asymmetry is the whole pattern.

The movement — converge onto the first 💡

The hallway: 🌑 🌑 🌑 💡 💡 💡 — find the first lit room. (dark = keep walking right · lit = keep it, look left)

The code

def first_true(lo, hi, lit):
    while lo < hi:                  # < : pinch down to ONE room
        mid = lo + (hi - lo) // 2
        if lit(mid): hi = mid         # 💡 lit → might be first → KEEP (not mid-1!)
        else:        lo = mid + 1     # 🌑 dark → border is later → drop it
    return lo                      # lo == hi == the first lit room
The hidden super-power: search on the ANSWER

The predicate doesn't need an array at all — it can run over a range of possible answers. “Min eating speed so Koko finishes in time?” → ok(speed) = canFinish(speed) is monotonic (faster always finishes), so binary-search the speed from 1…max. Same flip-finder, applied to a number line.

Anh đã thành thạo trò này từ hồi con nít rồi 🎯 — trò đoán số: Trò đoán số — chính là BS "Tao nghĩ một số từ 1 đến 100." Anh đoán 50 → tao nói "cao hơn". Anh đoán 75 → "thấp hơn"… ~7 lần là ra. Mỗi cú đoán + một câu "cao/thấp" trung thực → vứt nửa dải. Đó CHÍNH LÀ Binary Search — anh làm được nó trước cả khi biết code. The invariant — the promise that makes it correct

The first lit room is ALWAYS still inside [left, right]. A dark mid is proven worthless (drop it + everything left). A lit mid is never thrown away (keep it). You only ever delete rooms you've proven can't be the border — so when left and right finally touch, that one room must be the first lit one.
Câu hỏi cuối cùng, quan trọng nhất: tại sao được phép VỨT NỬA? Câu trả lời nằm gọn trong tính một-chiều. Nhìn ô giữa, đúng 2 khả năng: • Giữa = TRUE → vì "một khi true thì sau đó true mãi" → cả nửa phải đều true → điểm-lật (chỗ ĐẦU TIÊN thành true) không thể ở bên phải → vứt nửa phải. • Giữa = FALSE → mọi thứ bên trái càng false → điểm-lật chắc chắn ở bên phải → vứt nửa trái. Bằng chứng: bẻ gãy tính một-chiều là chết liền Nhớ trò đoán số chứ? Giả sử tao gian lận — lúc "cao hơn" lúc "thấp hơn" lung tung, không nhất quán. Anh đoán 50 → tao nói "cao hơn" → anh bỏ nửa trên. Nhưng tao xạo → biết đâu đáp án nằm ngay trong nửa anh vừa bỏ → vứt nửa = mất đáp án → sập tan tành. Chính cái lời hứa "reply một chiều, không lật lại" mới cho anh dám vứt nửa mà không sợ. Câu phải tự hỏi TRƯỚC mỗi bài BS: "Câu Yes/No của tao có một chiều không? Một khi CÓ, có CÓ mãi không?" — Có → BS được. Không → quên BS đi.

Lives in: first/last occurrence · insert position · min/max value that satisfies a condition (Koko, ship-in-D-days, split array).

Find exact asks “is mid the value?” and may finish early (<=, drop mid). Find boundary asks “is mid true?” and converges on the flip (<, keep mid). Same core: one test deletes half.

Where it breaks

Three traps.

  • Overflow: use mid = left + (right − left)//2, never (left+right)//2.
  • <= vs <: exact uses <= (check the lone cell); boundary uses < (converge).
  • mid vs mid+1: if a true mid could be the answer → right = mid (keep it), else you'd skip it.

You own it when…

  • Core idea in one line: a monotonic test → one check deletes half.
  • You can replay exact and say why mid is dropped (<=).
  • You can replay boundary and say why a true mid is kept (<, right=mid).
  • You can turn a “min/max that satisfies …” problem into search on the answer space.
