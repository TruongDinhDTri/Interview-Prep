Pattern 16 · Recognition

Linear DP

⚡ Thẻ nhận diện nhanh — liếc signal là ra bài.

🎯 Spot it

The signals that scream Linear DP.

One sequence, and the answer for n is built from the answer for smaller n (n−1, n−2) — and those smaller answers overlap.

Một dãy, đáp án của n dựa vào đáp án của n nhỏ hơn mà mấy cái nhỏ đó bị tính lại nhiều lần → tái dùng thay vì tính lại. Đó là Linear DP.
"how many ways / distinct ways"✓ count DP
"minimum steps / coins / operations"✓ optimize DP
"can you reach / is it possible?"✓ reachability DP
answer for n depends on smaller n✓ overlapping subproblems
"climb / jump / tile / decode"✓ classic linear DP
"generate all" / "list all"✗ → backtracking
Key: có overlapping subproblems — cùng một sub-answer bị cần đi cần lại nhiều lần. Tái dùng nó thay vì tính lại từ đầu.

🔀 DP vs Backtracking

Count/optimize, don't enumerate.

Backtracking — GENERATES paths. Signal = "generate all", "list all"✗ not DP
DP — COUNTS / OPTIMIZES using stored results. Signal = "how many", "min/max"✓ DP
Luật của Wiganz: "tái dùng kết quả cũ" = DP. Còn nếu bài đòi liệt kê ra từng lời giải thì đó là Backtracking, đừng nhầm.

⚙️ Why it works

The recurrence f(n) = f(n-1) + f(n-2) comes from asking one question: "What was the LAST decision that got me here?" The allowed moves define the recurrence.
"take 1 or 2 steps"f(n)=f(n-1)+f(n-2)
"take 1, 2, or 3 steps"+f(n-3)
"take 1 or k steps"f(n-1)+f(n-k)
Đừng giải thẳng bài lớn — hỏi bước cuối cùng nào dẫn tới đây, và những subproblem nào nuôi nó. Các nước đi cho phép chính là công thức truy hồi.

💻 The core

The move, in code.

Template 1 — Space-Optimized (O(1) space), preferred:

def climbingStairs(n: int) -> int:
    if n == 1: return 1
    prev1 = 1   # f(1)
    prev2 = 2   # f(2)
    for i in range(3, n + 1):   # range(3, n+1) — include n!
        curr = prev1 + prev2
        prev1 = prev2
        prev2 = curr
    return prev2
# Time: O(n) | Space: O(1)

Template 2 — Tabulation with full array (O(n) space):

def climbingStairs(n: int) -> int:
    if n == 1: return 1
    dp = [0] * (n + 1)
    dp[1] = 1
    dp[2] = 2
    for i in range(3, n + 1):
        dp[i] = dp[i-1] + dp[i-2]
    return dp[n]
# Time: O(n) | Space: O(n)

Template 3 — Memoization (Top-Down):

from functools import lru_cache

@lru_cache(maxsize=None)
def climbingStairs(n: int) -> int:
    if n == 1: return 1
    if n == 2: return 2
    return climbingStairs(n-1) + climbingStairs(n-2)
# Time: O(n) | Space: O(n) for cache + call stack
Ba cách viết, cùng một ý: base case → build lên tới n. Space-optimized chỉ giữ 2 giá trị cuối; top-down là recursion + cache.

🗂️ Same thing, different words

Bottom-up vs tabulation vs loop+reuse.

Bottom-upstart base cases → build to n
Tabulationfill a dp table cell by cell
Loop + reusewhat it looks like in code
Space-optimized tabulationtabulation, keep last K only
Bốn tên gọi trên đều là cùng một hướng. Còn top-down = recursion + cache (memoization) — hướng ngược lại.

⚠️ Traps

Where it breaks.

  1. Off-by-one in range: for n=3, range(3, n) is empty. Must be range(3, n + 1) to include n.
  2. Wrong swap order: prev1 = prev2 then prev2 = curr overwrites prev1 too early. Save the old value first — or keep the first swap and return prev2. Be consistent.
  3. Submitting pure recursion as DP: return f(n-1) + f(n-2) alone is O(2ⁿ), NOT DP. DP needs a cache (memo) OR a loop (tabulation).
  4. Missing base case guard: n=1 needs a guard (without it range(3, 2) is empty → returns 2, wrong — should be 1). n=2 does NOT (range(3, 3) empty → returns 2, correct).
  5. Confusing DP with Backtracking: about to write "generate all paths" → stop, that's Backtracking. "how many ways" → DP: count, don't enumerate.
Chết người nhất: (1) quên +1 trong range; (2) swap sai thứ tự mất prev1; (3) nộp recursion trần tưởng là DP. DP phải có cache hoặc loop.

🏅 Classic problems

The recurrences to know cold.

Climbing Stairs — base f(1)=1, f(2)=2f(n)=f(n-1)+f(n-2)
Fibonacci — base f(0)=0, f(1)=1f(n)=f(n-1)+f(n-2)
House Robber — can't rob adjacentmax(f(n-1), f(n-2)+nums[n])
Min Cost Climbing Stairs — take min pathmin(f(n-1)+cost, f(n-2)+cost)
Bốn bài này cùng một khung: đáp án của n = tổ hợp của n-1 và n-2. Khác nhau ở phép cộng (đếm) hay max/min (tối ưu).
