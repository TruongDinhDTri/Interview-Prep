Pattern 16 · Recognition

Linear DP

⚡ Thẻ nhận diện nhanh — liếc signal là ra bài.

📐 What it actually is

The DP whose table has one row.

Linear DP = one index is enough. If dp[i] — a single number — can name any subproblem, it's Linear. "Linear" means it literally: the table lies along a line, not a grid.

Định nghĩa gọn: bảng chỉ cần MỘT hàng. Một chỉ số dp[i] là đủ gọi tên một bài con. Chữ "Linear" nghĩa đen — bảng nằm trên một đường thẳng, không phải cái lưới.

Linear DP — Climbing Stairs

      i=1  i=2  i=3  i=4  i=5
dp = [ 1    2    3    5    8  ]
      ↑ ONE index → ONE row

2D DP — Unique Paths

      c0   c1   c2
 r0 │ 1 │ 1 │ 1 │
 r1 │ 1 │ 2 │ 3 │
 r2 │ 1 │ 3 │ 6 │
      ↑ TWO indices → a grid

Everything else in DP-land needs two numbers to name a subproblem — Unique Paths needs (row, col), Knapsack needs (item, capacity), String DP needs (position in s1, position in s2). All 2D. Linear DP is the one that needs just one.

The test: say the sentence "dp[i] is …" out loud. One index says it completely → Linear DP. Reaching for a second number → different shape.
Cách thử nhanh: nói thành câu "dp[i] là …". Nói trọn được bằng một chỉ số → Linear DP. Thấy cần thêm con số thứ hai → đó là shape khác (xem thẻ 17 để biết shape nào).

🧷 Why these problems share a folder

Stairs and burglary, same shelf.

Climbing Stairs, Fibonacci, House Robber, Min Cost Climbing Stairs — they look unrelated (bậc thang? trộm nhà?). They're grouped for exactly one reason:

One sequence, and the answer at position n is built from answers at smaller positions. That's the whole criterion.

The formula inside is a separate question — some of these add, some take a max. Don't expect the four problems to look alike; expect them to have the same shape of dependency.

Đây là chỗ dễ thấy vô lý: "leo cầu thang thì liên quan gì trộm nhà?". Liên quan đúng MỘT điểm — một dãy, đáp án ở n dựng từ đáp án ở vị trí nhỏ hơn. Còn công thức bên trong (cộng hay max) là chuyện khác, tính sau.

🎯 Spot it

The signals that scream Linear DP.

"how many ways / distinct ways"✓ counting DP
"minimum steps / coins / cost to reach"✓ optimizing DP
"can you reach / is it possible?"✓ reachability DP
answer at i depends on i-1, i-2, i-k✓ overlapping subproblems
"climb / jump / tile / decode / rob"✓ classic linear DP
you can say "dp[i] is …" with one index✓ 1D → linear
naming a subproblem needs two numbers✗ → 2D shape
"generate all" / "list all"✗ → backtracking
DP vs Backtracking: Backtracking sinh ra từng lời giải ("liệt kê hết"). DP đếm hoặc tối ưu bằng kết quả đã lưu ("bao nhiêu cách", "min/max"). Luật của Wiganz: "tái dùng kết quả cũ" = DP.

🗝️ Finding the recurrence

One question, every time.

Don't memorize f(n) = f(n-1) + f(n-2). Ask: "What was the LAST move that got me to i?" List every possibility, then join them.

Moves of 1 or 2 → last move came from i-1 or i-2dp[i-1]+dp[i-2]
Moves of 1, 2, or 3 → three places it could come from+dp[i-3]
Moves of 1 or kdp[i-1]+dp[i-k]
The formula changes; the question doesn't. The allowed moves ARE the recurrence.
Đừng học thuộc công thức — hỏi "bước CUỐI CÙNG đưa tôi tới i là gì?", liệt kê hết khả năng rồi nối lại. Đổi luật chơi (1-2 bậc → 1-2-3 bậc) thì công thức tự đổi theo, vì các nước đi cho phép chính là công thức.

➕ vs 🏆 The contrast

Why some add and some take max.

Both are Linear DP. Both look at dp[i-1] and dp[i-2]. But one adds them and the other picks one and throws the rest away — and that's not arbitrary:

Counting → +
The branches are distinct valid paths, and every one of them counts. Reaching step 4 via "…then a 1-step" and via "…then a 2-step" are two different sets of routes, both real. Add them to total them up.
→ Climbing Stairs, Fibonacci, Decode Ways
Optimizing → max / min
The branches are competing alternatives for the same single plan. You cannot both rob and not-rob house 3 in one night — those aren't two routes you tally, they're two proposals and you keep the better one.
→ House Robber, Min Cost Climbing Stairs

Walk it — houses [2, 7, 9, 3, 1]:

house 1 (2đ):  only one house         → dp = 2
house 2 (7đ):  can't take both 1 & 2  → max(2, 7)   = 7
house 3 (9đ):  rob  → 9 + dp[1] = 11
               skip → dp[2] = 7       → max(11, 7)  = 11
house 4 (3đ):  rob  → 3 + dp[2] = 10
               skip → dp[3] = 11      → max(10, 11) = 11
house 5 (1đ):  rob  → 1 + dp[3] = 12
               skip → dp[4] = 11      → max(12, 11) = 12  ✅

If you'd added 11 + 7 at house 3 you'd get 18 — a number matching no possible night of burglary. That's the tell: in an optimizing problem, adding the branches produces a meaningless number.

QUESTION ASKS JOIN WITH BECAUSE
"how many ways"+every branch is a separate valid route; total them
"max / min / best"max / minbranches compete for one plan; keep the winner
"can you reach it"orany one working branch is enough
Đây là chỗ file cũ chỉ liệt kê công thức max(...) mà không nói tại sao. Lý do: đếm thì các nhánh là những con đường khác nhau đều được tính → cộng. Tối ưu thì các nhánh là phương án cạnh tranh cho cùng MỘT kế hoạch → chỉ giữ cái tốt hơn. Cộng nhầm ở bài tối ưu sẽ ra con số vô nghĩa (11+7=18 — không đêm trộm nào ra được 18đ).

🗂️ The four questions

Every DP is these four answers.

# QUESTION CLIMBING STAIRS
1State — what does dp[i] mean?number of ways to reach step i
2Recurrence — how do smaller cells build it?dp[i] = dp[i-1] + dp[i-2]
3Base case — which cells are filled by hand?dp[1]=1, dp[2]=2
4Answer — which cell do I return?dp[n] — the last one
If you can't say #1 as a complete sentence, you don't have the problem yet. Everything downstream fails from a vague state.
Khung 4 câu này là của Foundations — dùng chung cho MỌI bài DP, không riêng Linear. Câu 1 (State) khó nhất: nói không trọn câu "dp[i] là …" nghĩa là chưa thật sự hiểu bài.

✅ Is it really DP?

Both must hold.

Overlapping subproblems — plain recursion recomputes the same f(k) from several branches. The Climbing Stairs tree is Fibonacci-shaped: f(3) appears under both f(5) and f(4).✓
Optimal substructure — to build f(5) you only need the result numbers of f(4) and f(3), not the individual routes inside them.✓
Hai điều kiện bắt buộc (học ở Foundations), áp vào Climbing Stairs: cây đệ quy tính lại cùng một f(k) nhiều lần ✓, và chỉ cần con số kết quả của bài con là ghép được bài cha ✓.

💻 The core

The move, in code.

Template 1 — Space-Optimized (O(1) space), preferred:

def climbingStairs(n: int) -> int:
    if n == 1: return 1
    prev1 = 1   # f(1)
    prev2 = 2   # f(2)
    for i in range(3, n + 1):   # range(3, n+1) — include n!
        curr = prev1 + prev2
        prev1 = prev2
        prev2 = curr
    return prev2
# Time: O(n) | Space: O(1)

Template 2 — Tabulation with full array (O(n) space):

def climbingStairs(n: int) -> int:
    if n == 1: return 1
    dp = [0] * (n + 1)
    dp[1] = 1
    dp[2] = 2
    for i in range(3, n + 1):
        dp[i] = dp[i-1] + dp[i-2]
    return dp[n]
# Time: O(n) | Space: O(n)

Template 3 — Memoization (Top-Down):

from functools import lru_cache

@lru_cache(maxsize=None)
def climbingStairs(n: int) -> int:
    if n == 1: return 1
    if n == 2: return 2
    return climbingStairs(n-1) + climbingStairs(n-2)
# Time: O(n) | Space: O(n) for cache + call stack
Ba cách viết, cùng một ý: base case → build lên tới n. Space-optimized chỉ giữ 2 giá trị cuối; top-down là recursion + cache.

🗂️ Same thing, different words

Bottom-up vs tabulation vs loop+reuse.

Bottom-upstart base cases → build to n
Tabulationfill a dp table cell by cell
Loop + reusewhat it looks like in code
Space-optimized tabulationtabulation, keep last K only
Bốn tên gọi trên đều là cùng một hướng. Còn top-down = recursion + cache (memoization) — hướng ngược lại.

⚠️ Traps

Where it breaks.

  1. Off-by-one in range: for n=3, range(3, n) is empty. Must be range(3, n + 1) to include n.
  2. Wrong swap order: prev1 = prev2 then prev2 = curr overwrites prev1 too early. Save the old value first — or keep the first swap and return prev2. Be consistent.
  3. Submitting pure recursion as DP: return f(n-1) + f(n-2) alone is O(2ⁿ), NOT DP. DP needs a cache (memo) OR a loop (tabulation).
  4. Missing base case guard: n=1 needs a guard (without it range(3, 2) is empty → returns 2, wrong — should be 1). n=2 does NOT (range(3, 3) empty → returns 2, correct).
  5. Adding when you should be maximizing — see the contrast above. If the branches are competing plans, + gives a number that means nothing.
  6. Confusing DP with Backtracking: about to write "generate all paths" → stop, that's Backtracking. "how many ways" → DP: count, don't enumerate.
Chết người nhất: (1) quên +1 trong range; (2) swap sai thứ tự mất prev1; (3) nộp recursion trần tưởng là DP; (4) cộng nhầm ở bài tối ưu. DP phải có cache hoặc loop.

🏅 Classic problems

The recurrences to know cold.

Climbing Stairs — counting · base f(1)=1, f(2)=2f(n-1)+f(n-2)
