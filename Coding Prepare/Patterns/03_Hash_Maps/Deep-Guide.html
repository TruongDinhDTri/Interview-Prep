The core idea

Trade memory for time.

The brute-force way to find a relationship between elements is to compare each one against all the others — O(n²) of re-scanning. The waste is that you keep re-discovering things you already walked past.

A hash map is a notebook with instant lookup. As you pass each element, you write down what you saw; for the next element you just ask the notebook — “have I already seen what I need?” — in O(1).

Store what you've seen; query in O(1). One pass, each element written once and asked once → O(n²) → O(n), at the cost of O(n) space. The skill is choosing what the key is and what the value answers.

① Complement lookup — “have I seen my partner?”

The matchmaker

Complement lookup

For each element, compute the partner you'd need and ask the map if it's already there. The map holds value → index.

The idea

Two Sum, unsorted. For num, the partner is target − num. If that partner is already in the notebook, done. Otherwise, write num down and move on. Look up BEFORE you store — else an element could match itself.

The movement — watch the notebook answer

The code

def two_sum(nums, target):
    seen = {}                          # value → index
    for i, num in enumerate(nums):
        need = target - num
        if need in seen:               # ASK before you store
            return [seen[need], i]
        seen[num] = i                  # write yourself down
    return []

Lives in: Two Sum (unsorted) · pair with given difference · “does a complement exist?” questions.

② Tally & group — “how many of each?”

The counter

Tally & group

Use the map as a set of buckets: the key is a property, the value is a running count (or a list). One pass tallies everything.

The idea

Frequency, anagrams, group-by — all the same move: derive a key from each element (the char itself; the sorted letters; the category) and bump its bucket. The whole distribution is built in O(n), then read instantly.

The movement — watch the buckets fill

Count letters in a a b c a b.

buckets · letter → count

The code

def counts(s):
    freq = {}
    for ch in s:
        freq[ch] = freq.get(ch, 0) + 1   # bump the bucket
    return freq
# anagram key  → tuple(sorted(word))
# subarray sum = K → prefix-sum counts in a map (see Prefix Sum)

Lives in: char/element frequency · group anagrams · subarray-sum-=-K (prefix counts) · “most common” questions.

Complement lookup asks the map “does my partner exist yet?” (key = value, value = where). Tally & group asks “how many / which group?” (key = property, value = count/list). Same core: write once, query O(1).

You own it when…

The test.

  • Core idea in one line: store what you've seen, query in O(1).
  • You can replay complement lookup and say why you ask before you store.
  • You can replay tally and pick the right key (raw value · sorted letters · category).
  • “Unsorted + pair + need indices” → Hash Map (not Two Pointers). “Sorted” → reconsider Two Pointers.
