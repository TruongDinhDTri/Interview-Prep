💡 What Does "0/1" Mean?

The binary constraint that defines the problem

The "Lucky Supermarket" Analogy

Imagine you're on a game show called "Siêu thị may mắn" (Lucky Supermarket):

  • The Bag: You get a bag that holds max 10kg — your constraint
  • The Items: TV, refrigerator, gold bars — each with weight and value
  • The Rule: You can only take items WHOLE. No breaking, cutting, or splitting.
💡

AHA Moment: The 0/1 Meaning

0/1 describes your choices for each item:

  • 1 = Take the entire item
  • 0 = Don't take it at all

There is no 0.5. No partial selection. It's binary.

The Rice vs Laptop Test

Question: "Between Rice and Laptop, which follows the 0/1 rule?"

❌ Rice (Fractional)

You can take 1kg, 0.5kg, or 0.1kg. If 1kg = $10, then 0.5kg = $5. Value scales with quantity.

✅ Laptop (0/1)

You cannot split a laptop. Breaking it makes it worthless scrap (value = 0). Take all or nothing.

🔑

Key Truth

The "0/1" in the name directly describes the constraint: each item exists in only two states — selected (1) or not selected (0). This binary nature is what makes the problem hard — you can't use "greedy" fractional approaches.

🧠 Why Dynamic Programming?

Understanding why brute force fails

Counting All Possibilities

With 3 items, each has 2 choices (take or leave):

Total combinations = 2 × 2 × 2 = 8 ways

📊

Exponential Growth

  • 3 items: 2³ = 8 combinations ✓
  • 10 items: 2¹⁰ = 1,024 combinations ✓
  • 20 items: 2²⁰ ≈ 1 million combinations ⚠️
  • 50 items: 2⁵⁰ ≈ 1,000,000,000,000,000 combinations 💀

At 50 items, brute force would take thousands of years to compute. This is why we need a smarter approach.

💡

The DP Philosophy

"Đừng tính lại những gì đã tính, hãy lưu nó vào một cái bảng"

"Don't recalculate what you've already calculated. Store it in a table."

The Core Idea

Instead of trying all 2ⁿ combinations, we build up solutions incrementally:

  1. Solve for smaller capacities first (0kg, 1kg, 2kg...)
  2. Solve for fewer items first (1 item, then 2, then 3...)
  3. Use previous answers to compute new ones

This reduces time from O(2ⁿ) to O(n × W) — exponential to polynomial!

The Two Choices at Every Cell
Option A: Skip Item

dp[i-1][w]

Look up same column, row above. Keep best result without this item.

Option B: Take Item

val[i-1] + dp[i-1][w - wt[i-1]]

Item value + look up remaining capacity from row above.

dp[i][w] = max(Option A, Option B)

🔑

Key Truth: The Inheritance Principle

"Nếu món đồ mới quá nặng, ta bê nguyên xi kết quả từ hàng trên xuống."

If the item doesn't fit → dp[i][w] = dp[i-1][w] (just copy from above). You don't lose everything — you inherit the best result from before!

⌨️ Từ bảng ra code

Mỗi dòng code = một việc trên bảng. Đọc code — nhìn hình ngay bên dưới.

Cả thuật toán chỉ là: đi qua từng ô của bảng, và ở mỗi ô hỏi đúng 3 câu. Trả lời xong 3 câu = xong ô đó. Hết bảng = xong bài. Đừng học thuộc code — hiểu 6 khối dưới là tự viết lại được.

1 Ý tưởng gốc: mỗi ô chỉ hỏi 3 câu

Toàn bộ khối if / elif / else bên dưới chỉ là 3 câu hỏi này viết ra Python:

Câu 1 Ô này có nằm ở biên (hàng 0 hoặc cột 0)? → có → điền 0
Câu 2 Món hiện tại có nhét vừa balo cột này không? → vừa → max(GIỮ, LẤY)
Câu 3 Nếu không vừa? → chép ô ngay trên xuống (GIỮ)

Giữ 3 câu này trong đầu — mọi dòng code phía dưới chỉ là dịch chúng ra.

Chú ý ngay từ đây: mảng Python đếm từ 0, nhưng bảng để hàng 0 cho "chưa món nào" — nên Guitar là Hàng 1. Lệch đúng 1 nấc (Khối 5 sẽ cần):

3 Hai vòng lặp = đi từng ô

Câu hỏi lớn: tại sao range(n+1) và range(W+1), chứ không phải n và W? Nhìn cái "+1" nằm ở đâu:

Số HÀNG 0 ∅+1 🎸2 📻3 💻 1 hàng móng (chưa món) + n=3 món = n+1 = 4 hàng
Số CỘT 0kg+1234 1 cột balo rỗng + W=4 mức cân = W+1 = 5 cột

Cái "+1" chính là hàng 0 / cột 0 (móng nhà ở Khối 4). Thêm nữa: range(k) trong Python chạy 0 → k−1 (không tới k). Muốn chạm tới đúng hàng n và cột W thì bắt buộc range(n+1), range(W+1):

for i in range(n + 1):        # đi xuống từng HÀNG: 0..n
    for w in range(W + 1):    # đi ngang từng CỘT: 0..W

6 Trái tim: max(GIỮ, LẤY) — và khi không vừa

Nếu món vừa balo (wt[i-1] <= w) → so 2 nhánh, lấy lớn hơn:

    matrix[i][w] = max(
        matrix[i-1][w],                       # GIỮ: ô ngay trên
        val[i-1] + matrix[i-1][w - wt[i-1]]   # LẤY: giá món + ô hàng trên tại cột dư
    )

🟢 GIỮ = bỏ qua món i, giữ y nguyên thành tích tốt nhất của hàng trên (cùng cột). 🟠 LẤY = nhét món i vào, rồi cộng thêm phần tốt nhất còn nhét được vào chỗ trống. max chọn cái to hơn — đó là toàn bộ quyết định.

Mổ xẻ nhánh 🟠 LẤY = val[i-1] + matrix[i-1][w - wt[i-1]] — từng mảnh:

val[i-1]Giá của MÓN đang xét. Chữ i-1 ở đây = sửa lệch chỉ số (Khối 5): đứng ở Hàng i, thuộc tính món nằm ở mảng chỉ số i−1.
matrix[i-1][…]"HÀNG TRÊN" = kết quả tốt nhất khi CHƯA có món i. Chữ i-1 ở đây nghĩa HOÀN TOÀN KHÁC: không phải sửa lệch, mà là "quay về lúc chưa xét món này" để mượn kết quả cũ. ⚠️ Cùng ký hiệu, khác lý do!
w − wt[i-1]Chỗ trống còn lại. w = sức chứa cột đang xét; nhét món i tốn wt[i-1] cân → dư w − wt[i-1] kg. Ta tra đúng cột "dư" đó ở hàng trên để lấp nốt phần trống.
💡

Điểm dễ lú nhất: HAI chữ i-1 KHÔNG cùng nghĩa

• val[i-1], wt[i-1] → i-1 vì mảng lệch chỉ số (lấy THUỘC TÍNH của món).

• matrix[i-1] → i-1 vì "hàng trên = phiên bản chưa có món i" (lấy KẾT QUẢ quá khứ).

# 1. Khai báo dữ liệu
val = [1500, 3000, 2000]
wt = [1, 4, 3]
W = 4
n = 3

# 2. Tạo bảng (Matrix) toàn số 0
matrix = [[0 for _ in range(W+1)] for _ in range(n+1)]

# 3. Vòng lặp điền bảng
for i in range(n + 1):
    for w in range(W + 1):
        if i == 0 or w == 0:          # Khối 4: biên
            matrix[i][w] = 0
        elif wt[i-1] <= w:               # Khối 6: vừa → max
            matrix[i][w] = max(matrix[i-1][w], val[i-1] + matrix[i-1][w-wt[i-1]])
        else:                            # Khối 6: không vừa → chép trên
            matrix[i][w] = matrix[i-1][w]

# 4. Kết quả = ô góc dưới-phải
print("Tổng giá trị lớn nhất:", matrix[n][W])  # Output: 3500

Code đầy đủ · 4 bẫy · checklist — tất cả để tra nhanh

# ==========================================
# 0/1 KNAPSACK — COMPLETE SOLUTION
# ==========================================

# 1. Input data
val = [1500, 3000, 2000]  # Values: Guitar, Radio, Laptop
wt = [1, 4, 3]              # Weights
W = 4                       # Bag capacity
n = len(val)               # Number of items

# 2. Create DP table (all zeros)
dp = [[0 for _ in range(W+1)] for _ in range(n+1)]

# 3. Fill the table
for i in range(n + 1):
    for w in range(W + 1):
        if i == 0 or w == 0:
            dp[i][w] = 0
        elif wt[i-1] <= w:
            dp[i][w] = max(
                dp[i-1][w],                       # Skip
                val[i-1] + dp[i-1][w - wt[i-1]]  # Take
            )
        else:
            dp[i][w] = dp[i-1][w]             # Inherit

# 4. Answer
print("Maximum value:", dp[n][W])

# 5. Backtrack for selected items
selected = []
currentW = W
for i in range(n, 0, -1):
    if dp[i][currentW] != dp[i-1][currentW]:
        selected.append(i-1)
        currentW -= wt[i-1]

print("Selected items:", selected)
# Output: Maximum value: 3500
# Output: Selected items: [2, 0]  (Laptop, Guitar)
dp[i][w] = max( dp[i-1][w], val[i-1] + dp[i-1][w - wt[i-1]] )
"Skip this item" vs "Take this item + best for remaining"

🐛 4 bẫy hay gặp (đã sống qua ở các scene)

🐛
  1. Sai range vòng lặp — range(len(val)) / range(len(wt)). Đúng: range(n+1) và range(W+1) (cột = sức chứa, KHÔNG phải số món).
  2. len(max(wt)+1) — vô nghĩa. Số cột = W+1.
  3. !== là JavaScript. Python dùng !=.
  4. Quên cập nhật sức chứa khi backtrack — phải dùng currentW đang giảm dần, không dùng w cũ.

📋 Checklist — quy trình giải mọi bài 0/1 Knapsack

  • 1
    Identify the constraint
    What limits selection? (weight, volume, time, budget...)
  • 2
    Create table: (n+1) × (W+1)
    Always add 1 for the "nothing" base case in both dimensions.
  • 3
    Initialize base cases
    Row 0 and Column 0 are all zeros.
  • 4
    Fill with recurrence
    Item fits? max(skip, take). Doesn't fit? Inherit.
  • 5
    Remember i-1 offset!
    Use wt[i-1] and val[i-1] because arrays are 0-indexed.
  • 6
    Backtrack for items
    Compare with row above. Different = taken.
🔑

Universal DP Principles

  1. Define the state clearly: What does dp[i][w] mean?
  2. Identify the recurrence: How does current depend on previous?
  3. Handle base cases first
  4. Fill in the right order
  5. Index with extreme care — off-by-one is the #1 bug
