Pattern 08

Fast & SlowPointers.

Two runners, different speeds, same track. Watch them race a real loop — and collide.

The core idea

Two runners. One twice as fast.

Send two pointers down the same path: 🐢 takes 1 step per move, 🐇 takes 2. Don't watch where they are — watch what happens between them. There are only two possible endings:

Straight track

🐇 reaches the end and runs off. It never meets 🐢. → no loop.

Looping track

There's no end. 🐇 keeps circling, gains 1 step on 🐢 each move, and taps it from behind. → they collide.

So a collision means the path loops. And if you instead lock the speeds (or give 🐇 a head start), you can make 🐢 stop on an exact spot — the middle, the n-th from the end.

Two speeds, same track. They collide ⟹ a loop exists. Lock the ratio ⟹ one runner lands on a chosen position. Why it's guaranteed: 🐇 gains exactly 1 step each move, so the gap ticks down 5→4→3→…→0 — it can never jump over the meeting point. O(n) time, O(1) space.

① The chase — do they collide?

Tortoise & Hare

Cycle detection

Both start at the head. On a loop, 🐇 (2×) laps the track and chases 🐢 (1×) down from behind. A collision is the proof the list loops.

The idea

Inside a loop there is no exit, so the faster runner cannot escape — it just keeps gaining ground. Because it earns +1 net step every move, the distance to 🐢 shrinks by 1 each time and must reach 0. No loop ⇒ 🐇 falls off the end first.

The movement — watch them race the ring & collide

A real loop: 3 → 4 → 5 → 6 → 7 → 8 → back to 3.

Why 2× and not 3×?

At 3× the gap drops by 2 each step: 5 → 3 → 1 → −1 — it can leap over 🐢 and miss. At 2× the gap drops by exactly 1 → it cannot skip 0. The collision is guaranteed, not luck.

The invariant

Once both are inside the loop, the gap strictly drops by 1 each step. A non-negative integer that loses 1 per step hits 0 in finite time → they provably meet.

The code

def has_cycle(head):
    slow = fast = head
    while fast and fast.next:      # guard BOTH → safe to hop twice
        slow = slow.next             # 1×
        fast = fast.next.next        # 2×
        if slow == fast: return True   # check AFTER moving (else equal at start)
    return False                    # hare fell off the end → no loop

Lives in: detect a cycle · find the cycle's start · is a linked list a palindrome.

② The stake-out — land on a spot.

Fixed ratio / offset

Position finding

No loop here — a straight list. Keep the speed ratio fixed so that when 🐇 hits the end, 🐢 is sitting exactly on the node you want.

The idea

🐇 at 2× covers the whole list while 🐢 at 1× covers exactly half — so 🐢 lands on the middle, one pass, no length count. (Offset version: give 🐇 a k-node head start; the gap stays k, so when 🐇 ends, 🐢 is on the n-th from the end.)

The movement — 🐇 races to the end, 🐢 lands on the middle

Straight list 1 → 2 → 3 → 4 → 5.

The invariant

🐢's distance from the head is always exactly half of 🐇's. So the instant 🐇 reaches the end (distance n), 🐢 is at n/2 — the middle — by construction.
The chase lets the gap close to zero — a collision proves a loop. The stake-out holds the gap steady so the follower lands on a position. Same engine — two speeds, one gap — two questions.

You own it when…

The test.

  • Core idea in one line: two runners, one twice as fast — watch what the gap does.
  • You can replay the ring chase and explain why the gap can't skip 0 at 2×.
  • You can replay the stake-out and say why 🐢 = n/2 when 🐇 = n.
  • You know the two rituals: move before checking, and guard fast and fast.next.
  • “Different speeds on a linked list” → Fast & Slow; “a pair on a sorted array” → Two Pointers.
