Pattern 02

SlidingWindow.

One core idea — and the two shapes it wears. Press step and watch a real window glide across the array.

⚡ Recognition — thẻ nhận diện nhanh →

The core idea

Don't recompute the window — slide it.

Checking every contiguous subarray means re-summing overlapping stretches again and again — that's the O(n²) waste. But two neighbouring windows share almost everything; they differ by just one element entering and one leaving.

Sliding Window keeps a live window and edits only its edges instead of rebuilding it. Each element is added once and removed once across the whole run.

One window, edited only at its two edges. Right edge adds, left edge removes — never re-scan the middle. Total edge-events ≤ 2n → O(n²) → O(n), O(k) space for whatever you track.

Shape one of two

① Fixed-size — a window of length K.

Constant width

Fixed-size

The window length K never changes. It just slides right: one in, one out, every step.

The idea

The problem hands you the size (“K consecutive”, “subarrays of length K”). When you slide one step, the new sum is the old sum minus the element leaving the left plus the element entering the right — sum = sum − arr[left] + arr[right]. You never re-add the K−1 elements that stayed.

The movement — watch the window slide right

Max sum of K = 3 consecutive in [2, 1, 5, 1, 3, 2].

The invariant

The window is always exactly K wide, and its running value is always correct. Because each slide repairs the value at both edges, you never recompute — so every window is read in O(1).

The code

def max_sum_k(arr, k):
    s = sum(arr[:k]); best = s        # first window
    for right in range(k, len(arr)):
        s += arr[right] - arr[right - k]   # add right, drop the one leaving
        best = max(best, s)
    return best

Lives in: max/avg sum of K consecutive · all subarrays of length K · fixed-window anagram counts.

Shape two of two

② Variable-size — grow, then shrink.

Breathing width

Variable-size

The window expands on the right while it can, and shrinks from the left when it must — its width breathes to obey a validity rule.

The idea

Right always marches forward, pulling new elements in. The moment the window breaks its rule, the left edge advances — removing elements — until the rule holds again. Track the best window seen while valid. No fixed size; the condition sets the size.

The movement — watch the window grow, then shrink

Longest substring with ≤ 2 distinct in a r a a c i. It grows to 4, then a 3rd letter forces it to shrink.

Two flavours — same window, opposite trigger

Longest valid

shrink WHILE invalid

Expand freely; only contract to restore validity. Record size after it's valid again.

Shortest valid

shrink WHILE valid

Once valid, contract greedily for the tightest fit. Record size before each shrink.

The invariant

After the shrink loop, the window is always valid. So the result you record is always from a legal window — and since left only moves forward, every index enters once and leaves once.

The code

def longest_k_distinct(s, k):
    left = 0; best = 0; freq = {}
    for right in range(len(s)):
        freq[s[right]] = freq.get(s[right], 0) + 1   # right edge ADDS
        while len(freq) > k:                       # rule broken → SHRINK
            freq[s[left]] -= 1
            if freq[s[left]] == 0: del freq[s[left]]
            left += 1                            # left edge REMOVES
        best = max(best, right - left + 1)         # window valid here
    return best

Lives in: longest substring (no repeats / ≤K distinct) · shortest subarray sum ≥ target · minimum window substring.

Fixed = constant K, pure slide (one in, one out). Variable = a breathing width ruled by a validity condition (Longest → shrink while invalid · Shortest → shrink while valid). Same core: edit only at the edges, never re-scan.

Reading a new problem

Which window — and is it a window?

Size given (“K consecutive”)? → Fixed. “Longest …”? → Variable, shrink while invalid. “Shortest / minimum window …”? → Variable, shrink while valid.

The one premise that must hold

Sliding Window only works on contiguous subarrays/substrings. The instant elements may be skipped (a subsequence), the window breaks — that's DP. And “find a pair” is Two Pointers, not a window.

You own it when…

  • Core idea in one line: edit the window at its edges, never re-scan.
  • You can replay the fixed slide and say why sum − left + right is O(1).
  • You can replay the variable breathing and name its invariant: after the shrink, the window is valid.
  • You map instantly: Longest → shrink-while-invalid, Shortest → shrink-while-valid.
  • “Non-contiguous / subsequence” → drop the window, reach for DP.
