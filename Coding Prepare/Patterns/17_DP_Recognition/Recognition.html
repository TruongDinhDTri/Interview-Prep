Pattern 17 · Recognition

DP Recognition

⚡ Thẻ triage — có phải DP không, và là shape nào.

🎯 Spot it

Is this DP — and which shape?

This card answers exactly two questions, fast: "Is this DP?" and "Which shape?" It does not teach theory, and it does not teach any single shape in depth.

Thẻ này chỉ làm triage — phân loại. Lý thuyết DP ở Foundations; từng shape học sâu ở folder riêng của shape đó (hoặc ở Deep-Guide của thẻ này).
Fastest single tell: "the answer for n depends on the answer for smaller n — and those smaller n's repeat."

1️⃣ Step 1 — Is this DP?

Thirty seconds. No theory.

Don't re-derive the definitions in the room. Run these three, in order:

  1. Write the plain recursion — the obvious brute force, no storage. Can you? → continue.
  2. Does it recompute the same argument? Trace two levels: does f(3) get called from more than one branch? → overlapping subproblems ✓
  3. Do you only need the child's RESULT to build the parent — not the details inside it? → optimal substructure ✓
All three → DP. Any one fails → not DP.
🧠 Fuzzy on WHY those two conditions are the requirement? That's theory, not triage — quay về Foundations → Dynamic Programming. Thẻ này giả định anh đã biết rồi, chỉ cần kiểm nhanh một bài thật.
Ba bước để làm, không phải để đọc: viết recursion trần → xem nó có tính lại cùng tham số không → xem có cần chi tiết bên trong bài con không (chỉ cần con số kết quả là đủ). Đủ ba → DP.

2️⃣ Step 2 — What kind of DP question?

This picks the operation.

"how many ways / distinct paths"count DP · join with +
"minimum / maximum cost, steps, coins"optimize · join with min/max
"can you reach / is it possible"reachability · join with or
"generate all / list all"✗ not DP → backtracking
Câu hỏi của đề quyết định phép nối các nhánh: đếm → cộng; tối ưu → max/min; hỏi có-được-không → or. Lý do đằng sau (tại sao đếm thì cộng mà tối ưu lại max) nằm ở 16 — Linear DP, và nó đúng cho mọi shape.

3️⃣ Step 3 — How many indices?

This picks the shape.

List two or three subproblems. Ask what differs between them. Count how many numbers it takes to name one.

MỘT con số → 1D → dp[i]  ·  HAI con số → 2D → dp[i][j]. Đây chính là câu hỏi chọn shape.
One sequence, a decision at each step ("take 1 or 2 steps", "rob or skip")
1 number — position i📏 Linear DP · 16 →
Items + capacity, each item used once
2 numbers — (item, capacity)🎒 0/1 Knapsack · 11 →
Items reusable without limit (coins, rod cuts, tiles)
2 numbers — (item, amount)🪙 Unbounded →
Two strings compared, aligned, transformed
2 numbers — (pos in s1, pos in s2)🧵 String DP →
A grid, moving through cells (right/down)
2 numbers — (row, col)🟦 2D Grid →

Unbounded Knapsack, String DP and 2D Grid DP don't have their own pattern folders yet — they live in this pattern's Deep-Guide, in the Shapes half.

Ba shape cuối chưa có folder riêng (Linear có 16, 0/1 Knapsack có 11) — chúng ở trong Deep-Guide của chính thẻ này, nửa "Shapes".

⚠️ Universal DP traps

Where it breaks.

  1. Plain recursion ≠ DP — you MUST add memoization or tabulation. f(n-1) + f(n-2) alone is O(2ⁿ).
  2. "Generate all" → Backtracking — if the answer is a list of solutions, not a count/min/max.
  3. Wrong loop direction for Knapsack — 0/1 = backward, Unbounded = forward.
  4. String DP needs 2D — one dimension per string. Don't flatten prematurely.
  5. Off-by-one on dp size — dp = [0] * (n + 1) not n, because dp[0] = base case.
  6. Greedy feels right but fails — construct a counter-example (coins=[1,3,4], amount=6 → greedy 4+1+1=3, DP 3+3=2) where local best leads to a globally worse result → reach for DP.
  7. Deciding the shape before defining the state — the shape follows from how many indices the state needs. Write "dp[…] is …" as a full sentence first; the shape falls out of it.
Bẫy top: (1) recursion trần tưởng là DP; (2) sai chiều loop knapsack (0/1 lùi, unbounded tới); (3) lệch +1 ở size dp; (4) chọn shape trước khi định nghĩa state — phải nói được câu "dp[…] là …" thì shape mới tự lòi ra.
