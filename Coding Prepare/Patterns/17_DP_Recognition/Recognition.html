Pattern 17 · Recognition

DP Recognition

⚡ Thẻ nhận diện nhanh — liếc signal là ra bài.

🎯 Spot it

Is this DP — and which shape?

The single clearest signal: "answer for n depends on the answer for smaller n — and those smaller n's overlap."

Dùng thẻ này TRƯỚC khi chọn sub-type. Nó trả lời 2 câu: "Đây có phải DP?" và "DP dạng nào?". Tell nhanh nhất: đáp án của n dựa vào n nhỏ hơn, mà mấy cái nhỏ đó lặp lại.
Quick gut-check: Can you write a plain recursion that solves it? → YES → does it recompute the same args? → YES → DP opportunity.
Viết được recursion trần mà thấy nó tính đi tính lại cùng tham số → đó chính là cơ hội DP. Tái dùng, đừng tính lại.

🧱 Layer 1 — Is this DP?

Two mandatory properties. Both must be true.

Overlapping Subproblems — same sub-answer needed many times. "f(3) inside f(5) AND inside f(4)"✓ reuse
Optimal Substructure — best of whole = built from best of parts. "min path through N uses min path to reach N"✓ build up
Thiếu MỘT trong hai → không phải DP. Phải vừa có subproblem lặp lại, vừa có "tối ưu tổng = ghép tối ưu các phần".

🌍 Layer 2 — The 5 DP question signals

What the problem asks → which DP.

"How many ways / distinct paths"✓ count DP · linear/2D
"Minimum / maximum cost, steps, coins"✓ optimize · linear/knap/2D
"Can you reach / is it possible"✓ reachability · linear/knap
"Take or skip each item, limited capacity"✓ knapsack · 0/1 or unbounded
"Compare / align two strings/sequences"✓ string DP · LCS/edit
"Generate all / list all"✗ → backtracking
Câu rõ nhất: "đáp án của n dựa vào n nhỏ hơn — và mấy n nhỏ đó chồng lấn nhau." Còn "liệt kê hết lời giải" thì là Backtracking.

🎨 Layer 3 — Which DP shape?

Pick the shape from the structure.

One sequence, decisions at each step
  ├─ "take 1 or 2 steps", "rob or skip", Fibonacci-style
  └─ → LINEAR DP            (see 16_Linear_DP)

Items with weight + capacity limit, each item once
  └─ → 0/1 KNAPSACK          (see 11_Knapsack_01_DP)

Items can be REUSED (coins, tiles)
  └─ → UNBOUNDED KNAPSACK    ↓

Two strings or sequences being COMPARED / ALIGNED
  └─ → STRING DP             (LCS, Edit Distance) ↓

Grid — move through cells (right/down)
  └─ → 2D GRID DP            ↓
Biết chắc là DP rồi thì nhìn cấu trúc mà chọn dạng: một dãy → Linear; item + sức chứa → Knapsack; hai chuỗi → String DP; lưới → 2D Grid.

🪙 Shape — Unbounded Knapsack

Items reused indefinitely + capacity/target.

Coin Change (min coins) — "any denomination, unlimited supply, make amount"min coins
Coin Change II (ways) — "how many ways to make amount"count ways
Cutting Rod — "cut into pieces of any length, maximize value"max value
Key difference from 0/1: inner loop goes FORWARD (allows reuse), not backward.
def coinChange(coins, amount):
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0
    for coin in coins:
        for a in range(coin, amount + 1):   # FORWARD → allows reuse
            dp[a] = min(dp[a], dp[a - coin] + 1)
    return dp[amount] if dp[amount] != float('inf') else -1
# Time: O(amount × coins) | Space: O(amount)

Trap: using a backward loop (the 0/1 pattern) on an unbounded problem → each coin used at most once → WRONG.

Item được dùng lại vô hạn + có target → Unbounded Knapsack. Nhớ: inner loop chạy TỚI (forward) để cho phép tái dùng.

🔬 Deep dive — Coin Change (#322)

Read the signals, then the recurrence.

"minimum number of" + "combinations/selections"optimize DP
Infinite supply of items + reach a targetunbounded knapsack
Subproblem inside subproblem of the SAME type — minCoins(15)→minCoins(10)classic DP shape
minCoins(10) called from many pathsoverlapping subproblems

Why greedy fails — a locally optimal pick blocks the global optimum:

coins = [1, 3, 4], amount = 6
Greedy: 4 + 1 + 1 = 3 coins  ❌
DP:     3 + 3     = 2 coins  ✅

Recurrence: dp(amt) = min(1 + dp(amt - coin) for each coin). Base: dp(0)=0, dp(negative)=inf (impossible path).

Top-Down (recursion + HashMap memoization):

def coinChange(coins, amount):
    memo = {}
    def dp(amt):
        if amt == 0: return 0
        if amt < 0:  return float('inf')
        if amt in memo: return memo[amt]
        memo[amt] = min(1 + dp(amt - c) for c in coins)
        return memo[amt]
    result = dp(amount)
    return result if result != float('inf') else -1
# Time: O(amount × coins) | Space: O(amount)

Bottom-Up (tabulation — the interview default): same as the Unbounded Knapsack block above. Time O(amount × coins), space O(amount).

Bất cứ khi nào greedy sai (chọn tốt cục bộ mà hỏng toàn cục) → rút DP ra. Top-Down dễ suy luận; Bottom-Up nhanh hơn, mặc định trong phỏng vấn.

🧵 Shape — String DP (LCS / Edit Distance)

Two strings — compare, align, transform.

Longest Common Subsequence — "longest subsequence in both"dp = LCS of s1[:i], s2[:j]
Edit Distance — "min operations to transform s1 → s2"dp = min edits
Longest Common Substring — "contiguous common portion"dp = len ending at i,j
Is Subsequence — "can s1 be found in s2 in order?"reachability DP
def lcs(s1, s2):
    m, n = len(s1), len(s2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if s1[i-1] == s2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1    # chars match → extend
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])   # skip one char
    return dp[m][n]
# Time: O(m×n) | Space: O(m×n)

Trap: String DP is almost always 2D — dp[i][j] where i indexes s1 and j indexes s2. Flatten it to 1D and you lose the cross-string relationship.

Hai chuỗi so/căn/biến đổi → String DP, gần như luôn 2D: một chiều cho mỗi chuỗi. Đừng ép về 1D quá sớm.

🟦 Shape — 2D Grid DP

Grid — top-left to bottom-right.

Unique Paths — "how many ways to reach bottom-right", right/down onlycount paths
Min Path Sum — "minimum cost path, right/down only"grid = costs
Triangle Min Path — "min path top to bottom"pyramid
Maximal Square — "largest square of all 1s"grid of 0/1
def uniquePaths(m, n):
    dp = [[1] * n for _ in range(m)]
    for i in range(1, m):
        for j in range(1, n):
            dp[i][j] = dp[i-1][j] + dp[i][j-1]   # from above + from left
    return dp[m-1][n-1]
# Time: O(m×n) | Space: O(m×n) → can optimize to O(n)

Space optimization: grid DP with only top/left dependency → keep only the previous row.

Đi trong lưới (thường chỉ phải/xuống), đếm đường hoặc tối ưu chi phí → 2D Grid DP. Chỉ phụ thuộc ô trên + trái nên nén được xuống một hàng.

⚠️ Universal DP traps

Where it breaks.

  1. Plain recursion ≠ DP — you MUST add memoization or tabulation. f(n-1) + f(n-2) alone is O(2ⁿ).
  2. "Generate all" → Backtracking — if the answer is a list of solutions, not a count/min/max.
  3. Wrong loop direction for Knapsack — 0/1 = backward, Unbounded = forward.
  4. String DP needs 2D — one dimension per string. Don't flatten prematurely.
  5. Off-by-one on dp size — dp = [0] * (n + 1) not n, because dp[0] = base case.
  6. Greedy feels right but fails — construct a counter-example (coins=[1,3,4], amount=6) where local best leads to a globally worse result → reach for DP.
Bẫy top: (1) recursion trần tưởng là DP; (2) sai chiều loop knapsack (0/1 lùi, unbounded tới); (3) lệch +1 ở size dp.
