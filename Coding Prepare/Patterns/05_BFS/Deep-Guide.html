Pattern 05

Breadth-FirstSearch.

One core idea — spread in rings, in strict order of distance. Shortest path and level-order both fall out of that order. Press step and watch the wave.

⚡ Recognition — thẻ nhận diện nhanh →

The core idea

Spread in rings, not dives.

Drop a stone in water: the ripple reaches everything 1 step away, then everything 2 steps away, and so on — a perfect expanding circle. BFS is that ripple over a graph.

Because the wave visits all distance-1 nodes before any distance-2 node, BFS walks the graph in strict order of distance from the source. That ordering IS the pattern — everything BFS is famous for falls out of it. A queue (first-in, first-out) is what keeps the rings in order.

A FIFO queue grows the frontier one ring at a time — visiting nodes in distance order. That order hands you two gifts for free: first arrival = shortest path, and each ring = one level to process. Mark a node visited the moment you enqueue it (not when you pop) so it's never queued twice. O(V+E).
Đừng đóng đinh BFS = "thuật tìm đường ngắn nhất" — cái đó là hệ quả, không phải bản chất. Bản chất BFS: duyệt theo ĐÚNG THỨ TỰ KHOẢNG CÁCH — nở trọn vòng 1 rồi mới chạm vòng 2. Từ cái thứ-tự đó, MỌI thứ BFS nổi tiếng tự rơi ra: (1) lần đầu chạm = đường ngắn nhất (vì vòng gần luôn tới trước), và (2) mỗi vòng = một "level" để xử lý (level-order, flood fill, multi-source). Giống hệt Binary Search: "shortest path" chỉ là một món quà của thứ-tự — như "sorted" chỉ là một cách có monotonic.

Shape one of two

① Level-order — count the rings.

Single source · shortest path

Level-order wave

Start from one source. Expand ring by ring, and the ring number is the distance. Process a whole level at a time to know which ring you're on.

The idea

Snapshot the queue size before each ring (for _ in range(len(queue))) — that's exactly the nodes at the current distance. Drain them, enqueue their unseen neighbours (the next ring), then steps += 1.

The movement — watch the wave expand

From source 🔴, flood the grid (walls are blocked) until the goal 🟢 is reached.

The code

from collections import deque
def bfs(start, target):
    q = deque([start]); seen = {start}; steps = 0
    while q:
        for _ in range(len(q)):       # snapshot ONE ring
            node = q.popleft()
            if node == target: return steps
            for nb in neighbors(node):
                if nb not in seen:
                    seen.add(nb)            # mark on ENQUEUE
                    q.append(nb)
        steps += 1
    return -1

Lives in: shortest path / min steps (unweighted) · level-order tree traversal · nearest-X.

Shape two of two

② Multi-source — many fires at once.

Many sources · flood

Multi-source flood

Seed the queue with every source at once. All fires spread together, so each cell burns from its nearest source automatically.

The idea

Same engine — only the starting point changes. One source = one fire. Many sources = many fires lit at the same moment. Every cell burns from the fire nearest to it, because the nearest fire arrives first — and once a cell is burnt, it's closed to the others. That's why one sweep gives every cell its distance to the closest source. (Rotting Oranges: the rotten cells are the fires; the last ring is when the last orange rots.)

Vẫn cái engine đó, chỉ đổi chỗ châm lửa. 1 nguồn = châm 1 chỗ. Nhiều nguồn = châm nhiều chỗ cùng lúc. Mỗi ô sẽ cháy bởi đám lửa gần nó nhất — vì lửa gần thì tới sớm hơn, mà cháy rồi là khoá, lửa xa tới sau vô ích. Nên một lượt quét là mọi ô đều có khoảng cách tới nguồn gần nhất. (Rotting Oranges: cam thối chính là các đám lửa; vòng cuối cùng = lúc cam cuối cùng thối.)

The movement — the forest burns

Why BFS, not DFS, for shortest?

DFS dives down one path to the bottom — it may reach the target by a long, winding route first. BFS reaches it by the shortest route first, because it never visits a far ring before a near one. Shortest/minimum ⇒ BFS. “Any path / all paths” ⇒ DFS.

Level-order = one source, ring number = distance. Multi-source = seed all sources at ring 0, every cell falls to its nearest. Same engine: a FIFO queue growing the frontier one ring at a time.

You own it when…

The test.

  • Core idea in one line: expand in rings; first arrival = shortest.
  • You mark visited on enqueue, and snapshot len(queue) to separate levels.
  • You can turn “min steps / nearest” into a BFS, and seed all sources for multi-source.
  • “Shortest unweighted” → BFS; “any/all paths” → DFS; “weighted” → Dijkstra.
