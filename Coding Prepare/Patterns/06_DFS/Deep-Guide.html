Pattern 06

Depth-FirstSearch.

One core idea — dive to the bottom, then report back up. The call stack is your memory. Press step and watch the answers bubble up.

The core idea

Go deep, then bubble back.

Where BFS spreads in rings, DFS picks one branch and follows it all the way down before trying anything else. When it can go no further, it backtracks one step and tries the next branch.

The magic is the return trip. A node often can't answer its own question until its children answer first — so DFS solves the children, and each one hands its result up to the parent, who combines them. The call stack remembers where to come back to.

Recurse down to a base case, combine results on the way up. Each node does: solve left, solve right, then combine(self, left, right). The recursion stack is the backtracking — no manual bookkeeping. O(V+E) time, O(height) space.

① Post-order — children answer first.

Trees · report up

Post-order (combine up)

When a node needs its children's results before its own — height, balance, “does every node satisfy …” — solve the subtrees first, then fold their answers into the node.

The idea

Max-depth: a node's depth is 1 + max(left, right), but you can't know that until both children report. So DFS reaches a leaf (returns 0), then each parent adds 1 to the taller child and passes it up. The answer assembles on the return trip.

The movement — watch depths bubble up

Compute the height of this tree. Each node lights when entered, turns green with its returned height.

The code

def height(node):
    if not node: return 0          # base: empty = 0
    L = height(node.left)            # solve children FIRST
    R = height(node.right)
    return 1 + max(L, R)           # combine, hand UP

Lives in: max depth · balanced tree (−1 sentinel) · validate BST (bounds down, truth up) · diameter · path sum.

② Graph flood — claim the whole region.

Graphs · visited set

Graph flood (components)

On a graph there are cycles, so you carry a visited set. From any unvisited node, DFS floods its entire connected region before you move on.

The idea

Number of islands: scan the grid; each time you hit unvisited land, that's a new island — DFS sinks every cell connected to it (marking visited), then you keep scanning. The flood guarantees you count each region exactly once.

The movement — flood each island

Count islands of land 🟫 in a sea 🟦. Each DFS flood paints one whole island.

Trees vs graphs — one difference

A tree has no cycles, so DFS never needs a visited set. A graph can loop back on itself, so you must track visited or you'll recurse forever. Same dive-and-backtrack engine; the set is the only guard.

Post-order = dive, then combine children's answers up (trees, no visited set). Graph flood = dive with a visited set to claim whole regions (cycles possible). Same engine: go deep, backtrack, the stack remembers.

You own it when…

The test.

  • Core idea in one line: recurse down, combine on the way up.
  • You spot “needs children first / height / balance / every-node” → post-order.
  • You add a visited set for graphs, and copy the path (path[:]) when collecting.
  • “Shortest / min steps” → BFS, not DFS. “Any path / all paths / components” → DFS.
