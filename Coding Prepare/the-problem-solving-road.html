Before the Interview

Prepare Before You Enter the Room

Before Step 0 — Prepare

Set yourself up so nothing technical distracts you.

Self-Introduction (under 1 minute)

"Hi, I'm Tri. I'm a software developer with 2-3 years of experience working with Python/Django and React. I've built full-stack applications and recently been focused on system design and algorithms. Excited to be here."

Environment Setup

  • Pen and paper ready (for drawing data structures)
  • Headphones on. Quiet room. Door closed.
  • Test webcam and audio 5 minutes early
  • Familiarize with coding platform shortcuts (CoderPad, CodePen, HackerRank)
  • Have water nearby — you'll be talking a lot

Mindset

  • "The first 3–5 minutes are for understanding." Don't touch the keyboard yet.
  • Silence = Strong No Hire. Think out loud, always.
  • It's a conversation, not a test. The interviewer wants you to succeed.

Step 0

Ground — Understand First, Solve Second

The first 3–5 minutes are for understanding. This is where Communication scoring begins.

Step 0 — Ground

"Do I actually understand what's being asked?"

💬 Communication 🧩 Problem Solving

Questions to ALWAYS ask:

  • Is the input sorted? (changes BTTC dramatically — e.g., O(n) → O(log n))
  • Can values be negative? Zero? Floating point?
  • Can there be duplicates?
  • Can the input be empty or null?
  • Can I modify the original input/data structure?
  • How is the input stored? (array, linked list, tree, graph with cycles?)
  • What's the expected input size? (affects whether O(n²) is acceptable)
  • What should I return? (index, value, boolean, new array, in-place?)
  • Is there only one valid answer, or could there be multiple?
Concrete Example — "Busiest Time in The Mall"
"Let me make sure I understand. I'm given an array of data points, each with a timestamp, visitor count, and direction — enter or exit. I need to find the timestamp when the mall had the most visitors. A few questions:

• Is the data sorted by timestamp? (Yes)
• Can multiple events share the same timestamp? (Yes)
• If there are multiple periods with the same peak, do I return the earliest? (Yes)
• What should I return — the timestamp or the visitor count? (Timestamp)
• Can visitor count be zero? (No, at least 1)"
  • Work through 1–2 small examples by hand — write input, trace through, write expected output and WHY

Step 1 — Decode

"What is this problem really asking?"

🧩 Problem Solving 💬 Communication

Problem Title Strip the story → Abstract problem
"Fruits Into Baskets" "Longest subarray with at most K distinct elements"

Step 2

Route — Pattern or First Principles?

Be honest about which road you're on. Forcing a pattern where none fits wastes more time than starting from scratch.

Step 2 — Route

"Do I recognize a known pattern here?"

🧩 Problem Solving

Three-question gate:

  • Does the abstract shape match a pattern signature?
  • Can I name the pattern AND explain why it applies?
  • Have I solved something like this with that pattern?
The Gate

Yes to all 3 → Pattern Path (Step 3P)

No to any → First Principles Path (Step 3F)

"I can think of two approaches here. The brute force would be checking every pair in O(n²). But I see this is a sorted array with a target sum — that's a Two Pointer signature, which would bring it to O(n). I'd like to go with the optimized approach — does that sound good?"

Why state multiple approaches: The rubric scores "multiple solutions with trade-off analysis" as an ADVANCED Problem Solving signal. Even 10 seconds naming the brute force before your real approach earns you points.

The Fork in the Road

Two Paths, Same Destination

Step 3P — Match

"What signals point to which pattern?"

  • Identify the signal keywords in the problem (substring, contiguous, sorted, target sum, shortest path, connected)
  • Name the pattern and explain why: "I see [signal] which tells me [pattern] because [reason]"
Concrete Example — "Longest Substring Without Repeating Characters"
"I see 'substring' and 'contiguous' — that's a Sliding Window signature. The constraint is 'no repeating characters,' which tells me when to shrink the window. I'll use a HashSet to track what's in the current window."

Step 4P — Reason

"WHY does this pattern work here?"

Answer three questions (A, B, C) before writing a single line of code:

Concrete Example — Longest Substring Without Repeating Characters

A. Brute force, and why is it bad?

"Check every possible substring, verify each has unique characters. That's O(n³) — O(n²) substrings × O(n) to check each. Way too slow."

B. What does this pattern do instead?

"Sliding Window: maintain one window with two pointers. Expand the right pointer to include new characters. When a duplicate is found, shrink from the left until the duplicate is removed. Each character is visited at most twice → O(n)."

C. What rule keeps it valid (invariant)?

"The window must contain only unique characters at all times. The moment a character repeats, we shrink from the left. This invariant guarantees every valid window is checked without rechecking old substrings."

Step 3F — Explore

"How would I solve this without patterns?"

Try these techniques in order. Stop when something clicks.

A. Visualize / Draw It

Draw the actual data structure on paper. For arrays, draw boxes with values. For trees, draw nodes and edges. For matrices, draw the grid.

Mall Problem — Timeline Visualization
Event Timeline
t1 = 1487799425
+14 enter −4 exit −2 exit
t2 = 1487800378
+10 enter
count: 0 → +14 = 14 → −4 = 10 → −2 = 8 check! 8 > 0 → peak = 8 → +10 = 18 check! 18 > 8 → NEW PEAK = 18

Works especially well for: trees, graphs, matrices, linked lists, any problem where spatial relationships matter.

B. Solve It Manually

Pretend you're not a programmer. Walk through the input step by step, tracking state at each point. Write down the concrete rules you discover.

Mall Problem — Step-by-Step Walkthrough

Input: [[1487799425, 14, 1], [1487799425, 4, 0], [1487799425, 2, 0], [1487800378, 10, 1]]

  1. Event: timestamp 1487799425, 14 people ENTER → count = 0 + 14 = 14
  2. Same timestamp, 4 people EXIT → count = 14 − 4 = 10
  3. Same timestamp, 2 people EXIT → count = 10 − 2 = 8
  4. ⚑ Timestamp changes next! Check peak: 8 > 0? Yes → best = 8, best_time = 1487799425
  5. Event: timestamp 1487800378, 10 people ENTER → count = 8 + 10 = 18
  6. ⚑ Last event! Check peak: 18 > 8? Yes → best = 18, best_time = 1487800378

Answer: 1487800378

Rules Discovered
  • Add on enter, subtract on exit
  • Only check for peak when timestamp changes or at the end
  • DON'T check mid-timestamp — events at same time must be batched

C. Generate More Examples

Try at least 3 inputs: a normal case, an edge case, and a tricky case. The tricky case is where the insight lives.

Mall Problem

Normal: [[t1, 5, 1], [t2, 3, 0]] → peak at t1 with 5

Edge: [[t1, 1, 1]] → single event, peak is t1

Tricky: [[t1, 10, 1], [t1, 3, 0]] → same timestamp! Must process both before checking. Count = 7, not 10.

D. Try Common Data Structures

Go through this decision table systematically:

If you need... Try... Example
O(1) lookup, counting, grouping HashMap Two Sum: store {value: index}, look up target - num
Parsing nested structure, matching Stack Valid Parentheses: push open, pop on close, check match
Top-K, min-K, median, priority Heap K Closest Points: max-heap of size K
Uniqueness, set operations Set Longest Substring: track chars in current window
String prefix lookup Trie Autocomplete: store dictionary, search by prefix

Mall Problem

"Do I need lookup? No. Counting? I just need a running counter. Stack? No nesting. Heap? No priority. This is simpler — just a single pass with a counter variable."

E. Decompose

Break the problem into smaller independent pieces. Solve each piece, then combine.

Mall Problem

Break into: (1) process each event (add/subtract), (2) detect timestamp boundaries, (3) check for new peak after each boundary.

Group Anagrams

Break into: (1) a function to hash a string into a canonical form, (2) a function to group strings by their hash.

F. Start with Brute Force

Get ANY working solution first. Often the brute force reveals the insight you need to optimize.

# First attempt — check peak after EVERY event (BUGGY)
def find_busiest_period_v1(data):
    count = 0
    max_count = 0
    max_time = 0
    for i in range(len(data)):
        if data[i][2] == 1:
            count += data[i][1]
        else:
            count -= data[i][1]
        if count > max_count:    # BUG: checking too early!
            max_count = count
            max_time = data[i][0]
    return max_time

# Returns t1 (count=14 after first event) — WRONG!
# Real peak at t1 is 8 (after all 3 events),
# peak overall is 18 at t2.
#
# Fix: only check when timestamp changes
# → that IS the optimal solution.

The brute force was 90% right. The bug (checking too early) pointed directly to the fix (check at timestamp boundaries). Brute force → insight → fix = optimal solution.

Step 4F — Build

"How do I optimize my insight?"

Apply these optimization techniques to improve your brute force:

1. Determine the BTTC (Best Theoretical Time Complexity)

The absolute minimum work required — you can NEVER beat this.

Task Why BTTC
Find sum of arrayMust look at every elementO(n)
Find number in sorted arrayBinary search possibleO(log n)
Find largest in sorted arrayIt's the last elementO(1)
Count groups of anagramsMust examine each word and characterO(nk)
Find islands in matrixMust examine each cellO(nm)

Why it matters: If your brute force is O(n²) and BTTC is O(n), there's room to optimize. If your solution is already O(n) and BTTC is O(n), the interviewer might want you to: (a) do it in a single pass instead of two, or (b) optimize space.

Mall Problem

"I must read every event → BTTC is O(n). My approach IS O(n) — one pass. Space is O(1). Can't do better."

"The BTTC here is O(n) because I need to examine every event at least once. My solution achieves this."

2. Identify Overlapping / Repeated Computation

Naive solutions often recalculate the same thing over and over.

Example — Product of Array Except Self

Brute force: for each index, multiply all OTHER elements → O(n²)

Notice: result[n] and result[n+1] share most of the same multiplications — tons of duplicated work

Fix: use a prefix product array. Precompute products from left, then from right → O(n)

"Am I computing the same sub-result multiple times? Can I store it and reuse?"

3. Try Different Data Structures

Is a lookup bottleneck slowing you down?

Example — K Closest Points to Origin

Naive: calculate all distances, sort, take K smallest → O(n log n)

Better: use a max-Heap of size K. For each point, add to heap; if heap > K, remove max → O(n log k)

The data structure change (array sort → heap) made the difference.

"Is my bottleneck a lookup (use HashMap), finding min/max (use Heap), or ordering (use sorted structure)?"

4. Eliminate Redundant Work

Specific micro-optimizations with examples:

(a) Don't check conditions unnecessarily:

Bad: if not arr and len(arr) == 0 — first check makes second redundant
Bad: x < 5 and x < 10 — second is subcondition of first

(b) Order your checks — fast before slow, unlikely before likely:

if fast() or slow() — if fast() is true, skip slow()
if unlikely() and likely() — if unlikely() is false, skip likely()

(c) Cache repeated method calls:

Bad: calling len(array) every iteration when it doesn't change
Fix: length = len(array) once at the start

(d) Early termination — return the moment you have the answer:

# BAD: scans entire array even after finding match
def contains(search, strings):
    result = False
    for s in strings:
        if s.lower() == search.lower():
            result = True
    return result

# GOOD: returns immediately
def contains(search, strings):
    search_lower = search.lower()  # compute once, outside loop
    for s in strings:
        if s.lower() == search_lower:
            return True
    return False

(e) Minimize work inside loops:

Bad: search_term.lower() called every iteration — it never changes
Fix: compute it once before the loop

(f) Lazy evaluation — don't compute until needed:

def contains(search, strings):
    if len(strings) == 0:
        return False  # skip .lower() entirely
    search_lower = search.lower()
    for s in strings:
        if s.lower() == search_lower:
            return True
    return False
⟐

Both paths merge here. You now have an approach and understand why it works.

Step 5

Discuss — Present, Compare, Get the Green Light

Work out and optimize your approach with the interviewer. Don't jump to code — discuss first.

Step 5 — Discuss

"Have I discussed my approach and gotten the green light?"

🧩 Problem Solving 💬 Communication
  • Present at least 2 approaches at a high level (brute force + optimized)
  • For each: state time complexity, space complexity, and the tradeoff
  • Discuss as if the interviewer is a coworker — collaborative tone
  • Use BTTC to justify your choice: "Since we must read every element, O(n) is optimal"
  • Conclude on which approach and WHY
  • Get explicit green light: "Shall I code this up?"

✓ DO

  • State time AND space complexity explicitly for each approach
  • Explain the tradeoff between approaches clearly
  • Listen for hints — the interviewer may steer you
  • Be collaborative: "What do you think?" / "Does this direction make sense?"

✗ DON'T

  • Don't jump straight to coding without discussing
  • Don't appear unsure — present with confidence
  • Don't ignore information or hints the interviewer gives
  • Don't go too deep into implementation details — stay at the approach level
Concrete Example — Two Sum
"I see two approaches. First, nested loops — check every pair. O(n²) time, O(1) space. Second, a HashMap — store each number's index, check if target minus current exists. O(n) time, O(n) space. The HashMap trades space for a big time improvement. I'd go with that. Sound good?"
Concrete Example — Busiest Time in The Mall
"My approach is a single pass. I maintain a running count — add on enter, subtract on exit. I only check for a new peak after processing all events at the same timestamp. O(n) time, O(1) space. Since I must read every event, this is already at BTTC. Shall I code this up?"

Rubric signal: "Multiple solutions with trade-off analysis" is an ADVANCED Problem Solving score. Even 10 seconds naming the brute force before your real approach earns you points.

Step 6

Plan & Code — Outline, Then Execute

Step 6 — Plan & Code

"What are the key steps to execute this?"

⌨️ Technical Competency 💬 Communication

Phase 1: PLAN — Outline key steps out loud before typing

Walk through the approach before touching the keyboard. Then code it.

Concrete Example — Longest Substring Without Repeating Characters
"Here are my key steps:
1. Left pointer at 0, HashSet for tracking, max_length = 0.
2. Expand right pointer, add character to set.
3. While character already in set: remove left character, move left pointer.
4. Update max_length = max(max_length, right − left + 1).
5. Return max_length."
Concrete Example — Busiest Time in The Mall
"Here are my key steps:
1. Initialize count = 0, max_count = 0, max_time = 0.
2. Loop through each event in data.
3. If entrance: add visitor count. If exit: subtract.
4. If next timestamp differs OR last element: check if count > max_count.
5. Return max_time."

You're not guessing — you're executing a plan you already understand.

Phase 2: CODE — Clean implementation with narration

✓ DO

  • Skeleton first: write the main function structure, leave helpers as pass/comments, then fill in
  • Descriptive variable names: current_visitors not c, max_timestamp not t (exception: i, j, n for loops)
  • Narrate every line out loud: "I'm initializing count to zero to track current visitors in the mall..."
  • Write real, compilable code — NOT pseudocode
  • Ask before using library functions: "Can I use collections.Counter here?"
  • Extract repeated logic into helper functions (DRY)
  • When cutting corners for time, say so: "I'd normally add input validation here, but I'll skip for time"

✗ DON'T

  • Don't interrupt the interviewer when they speak — they may be giving a hint
  • Don't use single-character variable names (except i, j, n)
  • Don't add excessive comments — clean code speaks for itself
  • Don't copy-paste code without re-reading and verifying it
  • Don't announce "I'm done" before testing
  • Don't write pseudocode — interviewers want working code
  • Don't go silent while coding — silence = lost Communication points

Step 7 — Verify

"Does it work? What breaks it?"

🧪 Testing 💬 Communication

Common Bugs (scan for these EVERY time):

  • Off-by-one (< vs <=, length vs length - 1)
  • Wrong comparison operator
  • Uninitialized variables / wrong initial value
  • Missing return statement
  • Missing base case in recursion
  • Modifying collection while iterating
  • Integer overflow (Python doesn't have this, but other languages do)

Two Complete Walkthroughs

One pattern problem. One first-principles problem. Every step filled with exactly what to say and do.

Demo 1 — Pattern Path
"Longest Substring Without Repeating Characters"
Ground "Given a string, find the length of the longest substring with all unique characters. Is it ASCII or Unicode? I should return the length as an integer. Can the string be empty? If so, I'll return 0."
Decode "Longest contiguous sequence of characters where no character appears more than once."
Route "'Substring' + 'contiguous' + 'constraint' → Sliding Window. I can name it, explain why, and I've solved similar problems. Pattern Path."
Match "Sliding Window with a HashSet. Expand right pointer, shrink left when duplicate found."
Reason "A: Brute force checks all substrings in O(n³). B: Sliding Window visits each char at most twice → O(n). C: Invariant — window always contains only unique chars."
Discuss "Two approaches. Brute force: check every substring — O(n³) time, O(n) space. Sliding Window with HashSet — O(n) time, O(min(n, charset)) space. The window approach is at BTTC since we must read every character. I'll go with sliding window. Sound good?"
Plan "Key steps: 1) left=0, HashSet, max_length=0. 2) Expand right, add to set. 3) While dup: remove left char, advance left. 4) Update max_length. 5) Return max_length."
Code Skeleton: left=0, char_set=set(), max_length=0. Expand right, if dup → remove left chars until unique. Track max.
Verify "" → 0. "a" → 1. "aaa" → 1. "abcabcbb" → 3 ("abc"). Time O(n), Space O(min(n, charset)).

Complete Code:

def lengthOfLongestSubstring(s):
    char_set = set()
    left = 0
    max_length = 0

    for right in range(len(s)):
        while s[right] in char_set:
            char_set.remove(s[left])
            left += 1
        char_set.add(s[right])
        max_length = max(max_length, right - left + 1)

    return max_length
Demo 2 — First Principles Path
"Busiest Time in The Mall"
Ground "Timestamped enter/exit events, sorted. Multiple events can share a timestamp. Return the timestamp with the most visitors. I confirmed: sorted by time, return earliest peak if tie, visitor count always ≥ 1."
Decode "+/− events grouped by timestamp. Find the timestamp where the running total reaches its maximum."
Route "No sliding window, no two pointers, no BFS/DFS. This doesn't fit a standard pattern. First Principles Path."
Explore "Drew a timeline — saw the count go up and down. Manually counted: add visitors on enter, subtract on exit. Key insight from the tricky example: must process ALL events at the same timestamp before checking for a new peak."
Build "BTTC = O(n) since I must read every event. My approach IS O(n) — single pass with a counter. Space O(1). The trick: only check for a new peak when the next timestamp is different (or at the last element)."
Discuss "My approach is a single pass — maintain a running count, add on enter, subtract on exit. Only check for a new peak after processing all events at the same timestamp. O(n) time, O(1) space. Since I must read every event, this is at BTTC. Shall I code this up?"
Plan "Key steps: 1) count=0, max_count=0, max_time=0. 2) Loop each event. 3) Add or subtract based on direction. 4) If next timestamp differs or last element: check peak. 5) Return max_time."
Code Variables: count, max_count, max_time. Loop through, add/subtract. Check at timestamp boundaries.
Verify Traced through example above. Edge cases: single event, all same timestamp, all exits after initial entries. Time O(n), Space O(1).

Complete Code:

def find_busiest_period(data):
    count = 0
    max_count = 0
    max_time = 0

    for i in range(len(data)):
        if data[i][2] == 1:  # entrance
            count += data[i][1]
        else:  # exit
            count -= data[i][1]

        # Check peak only after processing all events at same timestamp
        if i == len(data) - 1 or data[i][0] != data[i + 1][0]:
            if count > max_count:
                max_count = count
                max_time = data[i][0]

    return max_time

Quick Reference — The Road in 60 Seconds

  1. PREPARE: Self-intro under 1 min. Environment ready. "First 3–5 min = understanding."
  2. GROUND: Paraphrase out loud. Ask: sorted? duplicates? nulls? return type? size? Trace 1–2 examples by hand.
  3. DECODE: Kill the story. State the pure abstract problem.
  4. ROUTE: Can I name a pattern, explain why, and have I solved one like it? Yes to all 3 → Pattern. Otherwise → First Principles.
  5. PATTERN — MATCH + REASON: Name pattern from signals. Answer: brute force? what does pattern do instead? invariant?
  6. FIRST PRINCIPLES — EXPLORE + BUILD: Visualize → manual solve → more examples → data structures → decompose → brute force. Then optimize with BTTC, overlapping computation, data structure swaps, redundant work elimination.
  7. DISCUSS: Present 2+ approaches with time/space complexity. Explain tradeoffs. Get the green light: "Shall I code this up?"
  8. PLAN & CODE: Outline key steps out loud first. Then skeleton → descriptive names → narrate every line → real code, not pseudocode.
  9. VERIFY: Scan for off-by-one, missing returns, wrong operators. Test edge cases. Trace through one example. State time & space complexity.
  10. PROVE: (Practice only) Close everything. Repeat from memory.
