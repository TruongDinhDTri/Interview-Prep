🔀 Hai kiểu DFS — vì sao bài này KHÔNG cần return

Cú click giải thích tại sao LCA cần return dfs còn bài này chỉ cần dfs().

(A) MUTATION style — THIS problem

dfs trả None; đáp án tích lũy vào biến NGOÀI. Chỉ cần GỌI, khỏi return.

component = []        # biến ngoài hứng
def dfs(email):
    visited.add(email)
    component.append(email) # ghi ra ngoài
    for nb in adj[email]:
        if nb not in visited:
            dfs(nb)        # chỉ gọi
dfs(email)                 # bấm nút. xong.

(B) RETURN-VALUE style — LCA #236

đáp án CHÍNH LÀ giá trị return. Phải return dfs(x) để chuyền ra; gọi trần → vứt đáp án.

def dfs(node):
    if not node: return None
    left  = dfs(node.left)  # BẮT giá trị
    right = dfs(node.right)
    ...
    return answer        # đáp án = return
return dfs(root)         # phải return ra ngoài
🧠 Self-check reflex (đã drill) — sau khi viết def dfs, hỏi 2 câu:

1️⃣ Đã bấm nút chạy chưa? (đã GỌI nó chưa?)

2️⃣ Kết quả có nối dây ra ngoài chưa? (mutation biến-ngoài hay return?)

Hai câu này bắt sống cả bug 3 lẫn vết thương LCA. 🔥

🔢 Complexity — Wiganz tự derive từng bước

Gọi N = tổng số email trên tất cả account.

Phase 1 — build
O(N)
Phase 2 — DFS
O(N)
Phase 3 — sort
O(N log N) ← thống trị
O(N) + O(N) + O(N log N) → số hạng lớn nhất thắng → Time = O(N log N) · Space = O(N)

💡 DEPTH ≠ TOTAL CALLS

Ở Phase 2: tổng lời gọi = N (đó là time, vì visited guard ⇒ mỗi email DFS đúng 1 lần). Nhưng độ sâu đệ quy = số tầng chồng cùng lúc = chuỗi dài nhất = O(N) worst case (đó là space, stack). Hai thứ KHÁC NHAU dù đều = N: một là tổng công, một là cao nhất tại một thời điểm.

📐 Vì sao sort = O(k log k) — đào tới gốc bằng merge-sort

8 → 4 → 2 → 1   = 3 lần chia = log₂(8) = 3

log k = số TẦNG = số lần chia đôi k cho tới khi còn 1 → đó CHÍNH LÀ định nghĩa của log.
k = công MERGE mỗi tầng — mỗi tầng đụng cả k phần tử một lần.
Nhân lại: (k công/tầng) × (log k tầng) = k log k — sàn BTTC của mọi comparison sort.
