The MistakenEncounter.

Binary search is three lines of logic and a thousand ways to bleed. Three classic wounds — watch each one happen, then heal it.

First, the correct encounter

Walk it once, properly.

A sorted shelf. You halve the search space each step by comparing the middle to your target. Pick a target, then step through — watch left, mid, and right close in.

looking for 7 in a sorted array
left = 0, right = len-1. While left <= right: compute mid inside the loop, compare, then move the boundary past mid. Three rules — and each mistake below breaks exactly one of them.

Wound #1

The frozen middle.

mid computed once, before the loop.

MISTAKE 01

Mid never moves

The boundaries shrink, but the spotlight stays put.

The bug

mid = (left + right) // 2   # ← computed ONCE, before the loop
while left <= right:
    if nums[mid] == target:   # mid never changes!
        return mid
    # left/right move… but mid is stuck forever
Why it bleeds
Infinite loop. You keep narrowing left and right, but you keep checking the same cell. The answer is never re-examined, the boundaries oscillate, the loop spins forever.

The fix

while left <= right:
    mid = left + (right - left) // 2   # ← recompute EVERY iteration

left + (right - left)//2 over (left+right)//2 also dodges integer overflow in languages with fixed-width ints — a free habit worth keeping.

Wound #2

The off-by-one door.

Looping on left < right instead of left <= right.

MISTAKE 02

The single element slips through

When the search space narrows to one cell, the door closes too early.

The bug

while left < right:   # misses the last candidate
Watch it fail · nums = [5], target = 5
left = right = 05

left = 0, right = 0 → left < right is False → loop body never runs → returns -1. But 5 is right there. ❌

The fix

while left <= right:   # include the case left == right

With <=, the moment left == right you still inspect that one surviving cell. That cell is often the answer.

Wound #3

The phantom index.

right = len(nums) — one step past the edge of the world.

MISTAKE 03

Right starts out of bounds

The shelf has indices 0…len-1. Reach for len, and you grab air.

The bug

right = len(nums)   # index len is OUT OF BOUNDS
# first mid can land on len-ish → nums[mid] → IndexError
Why it bleeds
For a length-N array, valid indices run 0 to N-1. Starting right = N means mid can point at a cell that doesn't exist → IndexError (or a silent wrong read in C-like languages).

The fix

right = len(nums) - 1   # the last VALID index

Note: the len(nums)-1 + left <= right pairing is one consistent template (closed interval [left, right]). The other valid template uses right = len(nums) with left < right (half-open [left, right)). Pick one and never mix them — mixing is where these bugs are born.

Carry these out

The three vows.

  • Always recompute mid inside the loop — a frozen mid is an infinite loop.
  • Use while left <= right for the closed-interval template — so the lone surviving cell still gets checked.
  • Set right = len(nums) - 1 — the last real index, never one past the edge.
  • Bonus: left + (right-left)//2 beats (left+right)//2 — same answer, no overflow.
