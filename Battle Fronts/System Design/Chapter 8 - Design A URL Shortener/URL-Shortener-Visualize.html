✂️ URL Shortening Path

  • Client POSTs longURL
  • Web server checks DB for existing (idempotency)
  • If new: ID Generator → unique ID
  • Base62 encode ID → 7-char shortURL
  • Save to DB + cache
  • Return shortURL to client

↗️ URL Redirecting Path

  • Client GETs shortURL
  • Load Balancer routes to web server
  • Web server checks Redis cache first
  • Cache HIT: 301/302 redirect immediately
  • Cache MISS: query DB, populate cache, redirect
  • ~80% of requests served from cache

⚡ Performance Numbers

  • 1,160 writes/sec (URL creation)
  • 11,600 reads/sec (redirects)
  • ~80% cache hit rate
  • ~2,320 DB reads/sec (cache misses)
  • 365 TB storage over 10 years
  • 5 GB Redis for hot URLs

🔑 Key Design Decisions

  • 301 vs 302: analytics vs performance
  • Base62 over Base64: URL-safe chars
  • n=7 chars: covers 3.5T URLs (10yr)
  • Bloom filter: avoids DB read per create
  • Snowflake ID gen: distributed, no SPOF
  • LRU cache: serves 80% reads
