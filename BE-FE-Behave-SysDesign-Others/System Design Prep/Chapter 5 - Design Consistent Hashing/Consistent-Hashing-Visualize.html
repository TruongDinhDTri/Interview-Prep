With hash(key) % N, changing N by just 1 causes nearly every key to recalculate to a different server. This is the "musical chairs" problem — remove one chair and everyone scrambles to find a new seat.

Ring State

🎓 What You're Seeing

Only the keys between the new/removed server and its predecessor (counterclockwise) are affected. All other keys stay exactly where they are. This is O(k/n) redistribution vs O(k) for naive hashing.

🎓 What You're Seeing

With 1 vnode per server, one server may own 60% of keys while another owns 5%. As you increase vnodes, distribution approaches uniform. At 200 vnodes: ~5% std dev. At 100 vnodes: ~10% std dev. More vnodes = better balance, but higher memory cost.
