The Retention System

Overview & The 4 Pillars (Tap to expand)

Why Retention Matters

You can learn 100 patterns, but if you forget them in 2 weeks, you'll fail interviews. The Retention System ensures:

  • Spaced Repetition: Review material at optimal intervals (Anki)
  • Deep Processing: Crystallize learnings into your own words weekly
  • Error Prevention: Learn from mistakes, don't repeat them
  • Long-term Memory: Time Machine practice keeps old material fresh

The 4 Pillars

1. Daily Anki Reviews (10 min/day) ▼

When: 3:00-3:10pm every weekday (before coding session)

How:

  • ▸ Open Anki → review today's queue (5-15 cards, ~10 min)
  • ▸ For each card: recall your answer BEFORE flipping — no peeking
  • ▸ Rate honestly: "Again" if blank, "Good" if you recalled with effort, "Easy" if instant
  • ▸ Failed a card? Jot down WHY in your Error Log — patterns in failures reveal weak spots

2. Weekly Crystallization (1.5h every Saturday morning) ▼

⏰ When: Saturdays 10:00-11:30am

🎯 Purpose: Turn this week's learning into PERMANENT memory by:

  • Writing what you learned in your own words
  • Testing yourself without looking at solutions
  • Creating flashcards for patterns you struggled with

📋 The 5 Steps (90 min total):

⏱️ STEP 1 → Quick Scan (10 min) ▼

What to do:

  1. Open your problem list/tracker from this week
  2. Read through the problem titles (don't solve yet)
  3. Just remember: "Oh yeah, I did this one"

That's it. Just refreshing your memory.

⏱️ STEP 2 → Find What Was Hard (5 min) ▼

What to do:

  1. Look at your week's problems again
  2. Ask: "Which problems made me struggle the most?"
  3. Circle or highlight 2-3 patterns that felt confusing

Example:

  • • "Two Pointers felt tricky"
  • • "Sliding Window confused me"
  • • "Didn't understand when to use DFS vs BFS"
⏱️ STEP 3 → Write Your Learning Summary (30 min) ▼

What to do: Open a document and answer these 3 questions:

Question 1: What patterns did I learn this week?

Write each pattern + simple explanation in YOUR words

Example:

✅ Two Pointers
→ Use when you need to search from both ends of a sorted array
→ Move left pointer right, or right pointer left, depending on the condition

✅ Sliding Window
→ Use for subarray/substring problems
→ Expand window by adding elements, shrink when condition breaks

Question 2: What was the KEY INSIGHT that made it click?

The "aha!" moment for each pattern

Example:

Two Pointers Insight: SORT FIRST if array isn't sorted!
And move the pointer that gives you a CHANCE to improve.

Sliding Window Insight: Use a HashMap to track frequency inside the window.

Question 3: What mistakes did I make?

Write down what went wrong and how to avoid it

Example:

❌ Mistake: Forgot to skip duplicates in Two Pointers
✅ Fix: Always add "while (left < right && arr[left] == arr[left-1]) left++"

❌ Mistake: Didn't know when to shrink window
✅ Fix: Shrink when condition is violated (like when window sum > target)
⏱️ STEP 4 → Make Anki Flashcards (15 min) ▼

What to do:

  1. Open Anki (or your flashcard app)
  2. Create 3-5 cards from your summary above

Flashcard Examples:

Card 1:

Front: "When should I use Two Pointers pattern?"

Back: "When searching from both ends of a sorted array, or when you need to find pairs that meet a condition"

Card 2:

Front: "What's the first thing to do before using Two Pointers?"

Back: "SORT the array first if it isn't already sorted"

Card 3:

Front: "Two Pointers: Which pointer should I move?"

Back: "Move the pointer that gives you a CHANCE to improve (e.g., if sum too small → move left up; if sum too big → move right down)"

⏱️ STEP 5 → Test Yourself (30 min) ▼

What to do:

  1. Pick 2-3 problems you struggled with this week
  2. CLOSE all notes, close all solutions
  3. Try to solve them from memory
  4. Timer: Give yourself 15 min per problem max
  5. If stuck after 15 min → Look at a HINT only (not full solution)
  6. Finish the problem

Goal: Prove to yourself you can solve it WITHOUT looking at the answer

Example:

  • • Week 1: Struggled with "Two Sum II" → Redo it from scratch
  • • Week 2: Struggled with "Container With Most Water" → Redo from memory

✅ After These 5 Steps: You've transformed "I saw this pattern" into "I OWN this pattern" 🔥

3. Error Log Review (30 min every Saturday) ▼

⏰ When: Saturdays 11:30am-12:00pm (right after Crystallization)

🎯 Purpose: Turn your mistakes into learning opportunities by:

  • Systematically tracking what went wrong
  • Understanding WHY you made each mistake
  • Creating prevention strategies so you don't repeat them
  • Building a personal database of patterns to avoid

📋 The 4 Steps (30 min total):

⏱️ STEP 1 → Open Your Error Log (2 min) ▼

What to do:

  1. Open your Error Log file (keep it as a simple .txt or Google Sheet)
  2. Review all entries from this week
  3. Count how many mistakes you logged

If you don't have an Error Log yet:

  • • Create a new file: ErrorLog.txt or use Google Sheets
  • • Use the format below
⏱️ STEP 2 → Categorize Each Mistake (10 min) ▼

What to do: For each logged mistake, identify which type it is:

3 Types of Mistakes:

1️⃣ Conceptual Mistakes (misunderstood the pattern or approach)

Example:

  • "I used BFS when I should have used DFS"
  • "Didn't realize this was a Two Pointers problem"
  • "Confused when to use sliding window vs two pointers"

2️⃣ Implementation Mistakes (understood the approach but coded it wrong)

Example:

  • "Off-by-one error in loop condition"
  • "Forgot to handle empty array edge case"
  • "Used wrong variable name, caused bug"
  • "Forgot to initialize HashMap"

3️⃣ Time Management Mistakes (ran out of time or got stuck)

Example:

  • "Spent 20 min debugging syntax instead of rewriting"
  • "Didn't read problem carefully, solved wrong thing"
  • "Got stuck optimizing too early, should've done brute force first"

Mark each mistake in your log with category: [C], [I], or [T]

⏱️ STEP 3 → Write Prevention Strategies (10 min) ▼

What to do: For each mistake, write down HOW to prevent it next time.

Prevention Strategy Examples:

Mistake: Forgot to check for empty array

Prevention: "Always add edge case checklist at top of code: null, empty, single element"

Mistake: Used wrong pattern (BFS instead of DFS)

Prevention: "Ask myself: Do I need shortest path (BFS) or any path (DFS)?"

Mistake: Off-by-one error in loop

Prevention: "Always trace through loop with smallest example (n=1, n=2) before running"

Mistake: Spent too long stuck

Prevention: "Set 10-min timer. If stuck after 10 min → look at hint, don't waste time"

Fill in the "Prevention" column for each mistake

⏱️ STEP 4 → Update Anki with Edge Cases (8 min) ▼

What to do:

  1. Look at all your Implementation Mistakes from this week
  2. Identify tricky edge cases you missed
  3. Create Anki cards for them

Anki Card Examples:

Card 1:

Front: "What edge cases should I check for array problems?"

Back: "Empty array, single element, all same values, negative numbers, duplicates"

Card 2:

Front: "Two Pointers: What if array has duplicates?"

Back: "Add while loop to skip: while (left < right && arr[left] == arr[left+1]) left++"

Card 3:

Front: "When do I use BFS vs DFS in tree problems?"

Back: "BFS = shortest path, level-order, need all nodes at distance X. DFS = any path, recursion, easier to code"

Create 2-3 cards from this week's mistakes

⏰ When: Saturdays 2:00-3:30pm (starting Week 4)

🎯 Purpose: Prevent forgetting by revisiting old problems at strategic intervals AND deepen your understanding with each visit

📊 How Many Problems: 2-3 problems total per session (90 minutes)

  • Problem 1: From 2 weeks ago (35 min)
  • Problem 2: From 3-6 weeks ago (35 min)
  • Problem 3 (optional): Extra problem if you finish early (20 min)

📋 The 4-Step Process:

⏱️ STEP 1 → Pick Your Problems (5-10 min) ▼

What to do:

  1. Check the Time Machine Schedule table below to see which weeks to pull from
  2. Go to your problem tracker/list from those weeks
  3. Pick 2-3 problems based on these criteria:

🎯 Problem Selection Criteria:

Prioritize problems where you:

  • ✅ Struggled for >20 min the first time
  • ✅ Used hints or looked at solutions
  • ✅ Solved it but didn't feel 100% confident
  • ✅ Made mistakes in implementation
  • ✅ Want to strengthen that specific pattern

Avoid problems where you:

  • ❌ Solved instantly (<10 min) with perfect code
  • ❌ Found trivial/too easy
  • ❌ Already revisited 2+ times and crushed every time

Mix pattern types:

  • • Don't pick 2 Two Pointers problems — vary the patterns
  • • Example: Pick 1 Sliding Window + 1 DFS problem

Check visit count:

  • • First time revisiting? → Focus on "Can I remember the approach?"
  • • Second time revisiting (4-6 weeks)? → Focus on "Can I optimize and handle all edge cases?"
  • • Third+ time? → Focus on "Can I teach this? Explain variants?"

Example for Week 5:

  → Pick: "Longest Substring Without Repeating" (Sliding Window)

⏱️ STEP 2 → Solve From Memory (60-70 min total: ~30 min per problem) ▼

What to do:

  1. CLOSE all notes, close all solutions, close everything
  2. Read the problem statement fresh (pretend you've never seen it)
  3. Set timer for 25-30 minutes
  4. Try to solve the problem completely from memory

🧠 The Solving Process:

Minutes 0-5: Think Before Coding

  • • Don't jump straight to code!
  • • Ask yourself: "What pattern is this?"
  • • "What was the key insight when I first solved this?"
  • • "What's the time/space complexity I'm aiming for?"
  • • Sketch the approach on paper/whiteboard

Minutes 5-20: Code the Solution

  • • Write code from memory
  • • If you remember the structure: Write it out
  • • If fuzzy on details: Reconstruct the logic step by step
  • • Test with example cases as you go

Minutes 20-30: Test & Debug

  • • Run through edge cases
  • • Fix any bugs
  • • Verify it works correctly

If you get stuck after 10-15 min:

1. First, try these self-prompts:

  • • "What pattern was this?" → Try to remember
  • • "What was the hard part?" → Think back to first solve
  • • "What would the brute force be?" → Build from there

2. After 15-20 min stuck:

  • • Look at a SMALL HINT only (not full solution)
  • • Examples: "This uses a hashmap...", "Sort first, then..."
  • • Close the hint and try again

3. After 25-30 min total:

  • • Move to next problem, mark this one as "❌ Needs review"
  • • Don't spend more than 30 min — you have 2-3 problems!

If you solve it quickly (<15 min):

  • • ✅ Great! That pattern is solid in memory 🔥
  • • Before moving on: Can you answer:
  • → "Why does this work?"
  • → "What's the time/space complexity?"
  • → "What edge cases did I handle?"
  • • Move to next problem or STEP 3 (Deepen Understanding)

Example solving flow:

Problem: "Longest Substring Without Repeating Characters"

0-5 min: Remember: "This is Sliding Window!"
         Key insight: Expand right, shrink left when duplicate
         Sketch: left=0, right=0, hashset to track chars

5-20 min: Code the solution:
          - while right < len(s)
          - if s[right] not in seen: add to set, expand
          - else: remove s[left], shrink left
          - track max_length

20-25 min: Test with "abcabcbb" → Works! Returns 3
25-30 min: Edge cases: empty string, all same chars
          ✅ Solved in 23 min!
⏱️ STEP 3 → Deepen Your Understanding (10-15 min per problem) ▼

🎯 This is WHERE THE MAGIC HAPPENS!

After solving (or attempting) each problem, DON'T just move on. Take 10-15 min to deepen your understanding.

What to do after solving/attempting:

1️⃣ Analyze Your Solution (5 min)

If you SOLVED it:

  • • Compare your solution to the optimal one (if different)
  • • Ask: "Could I optimize this further?"
  • • Ask: "Did I handle all edge cases?"
  • • Ask: "Can I explain WHY this works to someone else?"

If you STRUGGLED or FAILED:

  • • Look at the solution now
  • • Ask: "What did I miss?"
  • • Ask: "What pattern concept did I forget?"
  • • Ask: "Where exactly did my thinking go wrong?"

2️⃣ Go Deeper Based on Visit Count

🔸 FIRST TIME Revisiting (2 weeks ago):

Focus: "Can I remember and reconstruct?"

  • ✅ Did I remember the pattern?
  • ✅ Did I remember the key insight?
  • ✅ What did I forget? (Write it down!)
  • → Action: If struggled → Add pattern template to Anki

🔸 SECOND TIME Revisiting (4-6 weeks ago):

Focus: "Can I optimize and handle variants?"

  • ✅ Can I optimize time/space complexity?
  • ✅ What edge cases did I miss the first time?
  • ✅ Can I solve a VARIANT of this problem?
  • → Example: "Longest Substring" → "Longest with K Distinct Chars"?
  • → Action: Try to modify the problem slightly and solve the variant

🔸 THIRD+ TIME Revisiting (6+ weeks ago):

  • ✅ Can I explain this to someone who's never seen it?
  • ✅ Can I draw a diagram showing how it works?
  • ✅ Can I identify the CORE PRINCIPLE behind this pattern?
  • → Example: Sliding Window → "Maintain a valid window, expand when possible, shrink when invalid"
  • → Action: Write a mini-explanation in your own words, as if teaching

3️⃣ Extract the Lesson (3 min)

Write down ONE key lesson learned:

  • • You made the same mistake again
  • • You want to remember the optimization trick

Don't add if:

  • • You solved it perfectly
  • • You already have a card for this pattern and it's working
⏱️ STEP 4 → Log Results (5 min) ▼

  • Your brain has to RECONSTRUCT the solution, not just recognize it

Key talking points:

Project Structure: my_project/ ├ apps/ # Modular apps (users, api, core) ├ settings.py # Configuration (dev/prod) ├ urls.py # URL routing wsgi.py # WSGI application

ViewSets vs APIViews:

  • ViewSets: Use for standard CRUD operations (list, create, retrieve, update, destroy). Automatic URL routing with DefaultRouter.
  • APIViews: Use for custom logic, non-CRUD endpoints (e.g., /api/stats/).

Serializers: Data validation + transformation layer. ModelSerializer for basic CRUD; SerializerMethodField for computed fields.

Authentication Methods:

  • JWT (JSON Web Tokens): Stateless, scalable, good for SPAs
    • Access token (short-lived, 15min) + Refresh token (long-lived, 7 days)
  • Session-based: Traditional, good for server-rendered apps
  • Token Auth: Simple, good for internal APIs

Permissions:

  • IsAuthenticated: User must be logged in
  • IsAdminUser: User must be admin
  • Custom permissions: Override has_permission() or has_object_permission()

JWT Token Flow:

1. User logs in → POST /api/token/ 2. Server returns: { "access": "...", "refresh": "..." } 3. Client stores tokens (localStorage or httpOnly cookie) 4. Client sends: Authorization: Bearer 5. Token expires → Use refresh token to get new access token

  • Authorization Code Flow for third-party login (Google, GitHub)
  • Client credentials for server-to-server
  • Know the flow: Redirect → Auth code → Exchange for token

Key talking points:

Normalization Principles:

  • 1NF: Atomic values (no arrays in fields)
  • 2NF: No partial dependencies
  • 3NF: No transitive dependencies
  • When to denormalize: Read-heavy systems, performance critical (e.g., caching user's post count)

Query Optimization - The Big Two:

1. select_related() — For ForeignKey and OneToOne

# BAD: N+1 queries (1 + 100 = 101 queries)
applications = Application.objects.all()
for app in applications:
    print(app.user.name)  # Hits DB every time!

# GOOD: 1 query with JOIN
applications = Application.objects.select_related('user').all()
for app in applications:
    print(app.user.name)  # No extra query!

2. prefetch_related() — For ManyToMany and reverse ForeignKey

# BAD: N+1 queries
companies = Company.objects.all()
for company in companies:
    print(company.applications.count())  # Hits DB every time!

# GOOD: 2 queries (1 for companies, 1 for all applications)
companies = Company.objects.prefetch_related('applications').all()
for company in companies:
    print(company.applications.count())  # No extra query!

Indexing Strategy:

  • Index fields used in: WHERE clauses (filtering), ORDER BY (sorting), JOIN conditions (foreign keys auto-indexed)
  • Example: db_index=True on status, created_at for application tracking
  • Don't over-index: Each index slows down writes

Many-to-Many Through Models:

class Enrollment(models.Model):
    student = models.ForeignKey(Student)
    course = models.ForeignKey(Course)
    enrolled_date = models.DateField()  # Extra data!
    grade = models.CharField(max_length=2)
